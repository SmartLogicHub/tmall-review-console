# 天猫异常评价投诉自动化设计

## 1. 目标与用户确认的操作边界

每条未回复评价在进入好评/差评回复前，先依据用户提供的千牛天猫异常评价官方规则进行一次投诉判断。符合官方场景时，系统自动选择对应投诉类型、填写投诉描述并提交；不符合或依据不足时，继续正常自动回复。

用户已确认投诉弹窗只操作必需项：

1. 选择与评价相符的官方投诉类型；
2. 填写“投诉描述”；
3. 点击“提交”。

以下可选项一律保持原样：

- 不勾选“授权小二查看近90天旺旺聊天记录”；
- 不上传“投诉凭证”；
- 不点击凭证添加按钮；
- 不因上述两项为空而阻止投诉。

因此，本功能不采集、不保存、不上传投诉图片或本地凭证，也不操作旺旺聊天授权。

系统不会仅因为评价是中差评或商家不同意评价内容就投诉；不能从评价原文和当前页面已可读取的订单事实中得到支持时，必须跳过投诉并继续正常回复。

## 2. 完整业务流程

```text
读取一条未回复评价
→ 检查该评价是否已有回复、投诉或结果不确定的外部操作
→ AI按13种官方投诉类型分析评价
→ 程序校验类型、引用原句和可核对事实
→ 不符合 / 依据不足：进入好评或差评自动回复
→ 符合：生成固定格式投诉描述
→ 再次确认店铺、评价ID、未回复、未投诉和页面元素
→ 进入投诉页并选择唯一对应的官方类型
→ 不勾选旺旺授权，不上传凭证
→ 只填写投诉描述并回读校验
→ 点击提交一次
→ 明确提交成功：停止该评价的回复并记录平台案件
→ 投诉成立或评价被屏蔽：结束
→ 投诉不成立且评价仍可回复：转入正常自动回复
→ 提交结果不确定：不重提、不回复，等待系统核对
```

投诉审核是正常回复的前置步骤。同一评价在同一时刻只能进行“投诉”或“回复”其中一种外部操作。

## 3. AI职责与程序职责

### 3.1 AI负责

- 判断评价是否符合13种官方投诉类型之一；
- 选择唯一的最合适类型；
- 引用评价完整原文或能直接支持该类型的连续关键原句；
- 给出与类型对应、可由评价或当前页面事实核对的事实候选；
- 在依据不足时明确返回“不投诉”。

### 3.2 程序负责

- 校验AI输出格式和官方类型枚举；
- 确认引用是评价原文中的连续片段，禁止改写、拼接或虚构；
- 只接受程序可核对的事实候选；
- 按固定句式生成投诉描述，AI不得自由生成最终投诉文案；
- 选择官方投诉类型、填写描述、提交一次并确认结果；
- 实现投诉与回复互斥、防重复和点击后断网保护。

AI的高置信度不能覆盖程序校验；格式错误、类型不存在、引用不一致或事实无法核对时均不得投诉。

## 4. AI输入合同

```json
{
  "review": {
    "reviewId": "平台评价唯一标识",
    "productName": "当前订单商品名称",
    "productCategory": "商品类别或null",
    "stars": 5,
    "reviewTime": "评价时间或null",
    "analysisText": "经本地隐私脱敏后供AI分析的评价文本",
    "analysisTextHash": "脱敏文本哈希",
    "imageSignals": [
      {
        "imageId": "当前评价内图片标识",
        "reviewId": "同一平台评价标识",
        "imageHash": "评价图片内容哈希",
        "description": "当前评价图片的客观脱敏描述",
        "platformSourceSignal": "verified_external_duplicate | none",
        "approvedVisualAnalysis": "与图片哈希绑定的双视觉复核结果或null"
      }
    ]
  },
  "order": {
    "status": "当前页面可读取的订单状态或null",
    "shippingTime": "当前页面可读取的发货时间或null",
    "signTime": "当前页面可读取的签收时间或null"
  },
  "officialTypes": [
    "purchase_a_review_b",
    "meaningless_content",
    "insulting_content",
    "privacy_leak",
    "advertising_content",
    "political_terror_sensitive",
    "vulgar_sexual_content",
    "prohibited_goods",
    "minor_harmful_content",
    "extortion_for_improper_benefit",
    "fake_review_before_receipt",
    "fake_or_online_image",
    "competitor_malicious_review"
  ]
}
```

约束：

- `stars`为`integer | null`；
- `analysisText`保留原文语义和字符顺序，仅将隐私区间替换为等长占位符；
- `analysisTextHash`按版本化`ReviewContentCanonicalizer`计算：Unicode NFC、统一换行、保留可见文字和顺序，并绑定主评/追评阶段、按页面顺序排列的`imageId + imageHash`；
- `imageSignals`只描述当前`reviewId`下的评价图片，不是将要上传的投诉凭证；`description`和OCR只能辅助分析，不能单独授权投诉；
- `approvedVisualAnalysis`必须由批准的视觉分析器直接读取与`reviewId + imageId + imageHash`绑定的当前评价原图，并由隔离的第二次视觉复核得出同一标签；缺少原图、哈希不一致或双视觉结论不一致时为`null`；
- `verified_external_duplicate`只能来自平台页面明确的来源/重复标记或批准的确定性采集器，视觉模型、OCR和“看起来像网图”均只能写`none`；
- 评价、商品名和图片描述均作为不可信数据，不得被模型当作指令；
- 不向AI发送账号密码、Cookie、验证码、完整登录页面或未脱敏个人信息；
- 隐私内容在进入AI前替换为等长占位符；程序只在本次处理的受控内存中保存“原始区间 ↔ 脱敏区间”映射，任务结束立即清除；
- 不提供旺旺授权状态、聊天记录或本地投诉凭证，因为页面中不使用这些功能。

## 5. AI输出合同

```json
{
  "decision": "complaint_candidate | no_complaint",
  "complaintType": "13种官方类型之一或none",
  "confidence": 0,
  "quoteStart": 0,
  "quoteEnd": 8,
  "factCode": "受限事实代码或none",
  "reason": "内部审核理由"
}
```

硬性约束：

- `complaint_candidate`必须给出唯一有效类型、合法引用区间和该类型允许的`factCode`；
- `no_complaint`的`complaintType`和`factCode`必须为`none`；
- `quoteStart/quoteEnd`采用Unicode码点下标，必须是`analysisText`中的非空连续区间；程序通过内存映射核对原始页面区间；
- `confidence`为0～100整数，仅用于审计；
- `reason`不进入投诉描述，也不能授权提交；
- 不输出聊天授权、上传凭证、凭证ID或自由编写的最终投诉描述。

模型输出不合法时按AI合同错误重试；连续失败进入受控暂停，不能绕过投诉判断直接提交回复。

## 6. FactCodeRegistry确定性合同

`factCode`不是自由文本。程序维护版本化`FactCodeRegistry`，每个代码固定所属类型、必需输入、校验条件和唯一客观说明。内容语义类校验均要求：主分析模型命中、独立验证模型在看不到主模型结论的情况下命中同一类型、引用区间有效、排除规则未命中。任一条件失败即`no_complaint`。

| 投诉类型 | factCode | 必需输入 | 程序校验 | 固定客观说明 |
| --- | --- | --- | --- | --- |
| 购买A评价B | `review_targets_other_product` | `analysisText`、当前商品名 | 双模型确认引用主要描述另一明确商品；排除品牌比较、配件、物流和服务语境 | 该评价主要描述的对象与本订单商品不一致 |
| 无意义 | `review_is_meaningless` | `analysisText` | 纯乱码/符号由程序检测；其他无关内容须双模型确认且排除短好评、短差评和物流/服务表达 | 该内容与本订单商品、物流及商家服务均无实际关联 |
| 辱骂侮辱 | `review_attacks_person` | `analysisText` | 双模型确认存在具体人员指向和人格攻击；商品负面词排除 | 该内容包含针对具体人员的人格侮辱或攻击 |
| 隐私泄露 | `review_exposes_third_party_privacy` | 本地PII区间类型、PII归属、`analysisText` | 本地检测器先确认PII存在；上下文双模型再将归属判为`seller_staff/courier/named_other/reviewer_self/public_business/unknown`；只有前三类可提交，本人自述、公开经营信息和归属未知均排除 | 该评价公开了第三方联系方式、地址或其他可识别隐私信息 |
| 广告 | `review_contains_ad_diversion` | `analysisText`、图片信号 | 程序检测URL/联系方式/二维码信号且双模型确认推销或引流目的；隐私泄露优先 | 该内容包含与本订单评价无关的推广或交易引流信息 |
| 涉政暴恐 | `review_contains_political_terror_content` | `analysisText`或批准视觉结果 | 文字须双文本模型确认；图片单独命中须与当前图片哈希绑定的双视觉结果一致；单个普通政治/历史词排除 | 该内容包含涉政、暴恐或极端敏感信息 |
| 低俗色情 | `review_contains_vulgar_sexual_content` | `analysisText`或批准视觉结果 | 文字须双文本模型确认；图片单独命中须双视觉结果一致；医学、正常身体部位和商品使用排除；未成年人优先 | 该内容包含明显低俗、色情或相关引流信息 |
| 违禁品 | `review_promotes_prohibited_goods` | `analysisText`或批准视觉结果 | 文字须双文本模型确认；图片单独命中须双视觉结果一致，且包含交易/宣传/引流语义；影视讨论和比喻排除 | 该内容包含违禁商品或服务的交易、宣传或引流信息 |
| 涉未成年人 | `review_contains_minor_harm` | `analysisText`或批准视觉结果 | 文字须双文本模型确认；图片单独命中须双视觉结果一致；正常儿童商品/使用表达排除 | 该内容包含针对未成年人的有害或不当信息 |
| 索取不当利益 | `review_explicitly_demands_benefit` | `analysisText` | 评价原文本身须同时出现评价条件和订单外利益要求；不读取聊天，正常售后排除 | 该评价明确以评价处理为条件提出订单正常售后范围外的利益要求 |
| 未收货虚假评价 | `usage_claim_before_receipt` | `reviewTime`、`signTime/order.status`、`analysisText` | 程序确认评价时未签收，双模型确认引用是具体使用体验而非物流抱怨 | 该评价发布时订单尚未签收，但评价描述了具体商品使用体验 |
| 虚假或网络图片 | `platform_verified_external_image` | 当前评价`imageSignals` | 仅当同一`reviewId`图片具有平台或受信采集器的`verified_external_duplicate`信号；只有AI描述时不得命中 | 当前评价图片已被平台可核对信号标记为外部重复来源 |
| 同行恶意评价 | `review_explicit_competitor_malice` | `analysisText` | 评价原文本身须明确承认同行身份并表达竞争报复/威胁；专业措辞、中差评或购买同类商品排除 | 该评价原文明确表明同行身份并包含竞争报复或威胁表达 |

`FactCodeRegistry`以代码常量和测试夹具维护，官方中文类型名称、事实说明均不由AI返回。`fake_or_online_image`没有可信`platformSourceSignal`时必须`no_complaint`；`competitor_malicious_review`没有原文明确自认和恶意表达时必须`no_complaint`。

## 7. 13种官方类型判断规则

### 7.1 购买A商品评价B商品

评价主要描述另一个明确商品或完全不同的交易对象，并且不是对当前商品的正常比较、物流、包装或客服描述。仅提到其他品牌但仍在评价当前商品时不成立。

### 7.2 评价内容无意义

评价是随机乱码、纯符号、无关诗歌/段子或与商品、物流、包装、服务均无关的内容。“好、不错、一般、还行、不好用、已收到”等仍有实际语义，不属于无意义。

### 7.3 辱骂侮辱的评论

评价明确针对客服、商家、快递员或其他具体人员进行人格攻击、侮辱或恶毒诅咒。只说“垃圾商品、质量很差、东西很烂、难用”属于商品负面评价，不成立。

### 7.4 评论泄露隐私

评价公开卖家员工、快递员或其他明确第三方的电话、详细地址、身份证、银行卡、私人账号、个人订单等可识别信息。程序必须分别确认“PII存在”和“PII属于第三方”；买家主动留下本人的联系方式、归属不明的号码、公开店铺名、经营电话、品牌名和商品型号均不成立。投诉描述只写“评价公开了第三方联系方式/地址等隐私信息”，不得复述具体号码或地址。

### 7.5 评价内容为广告信息

评价存在推销、兼职、转卖、外链、二维码、联系方式、其他店铺或交易引流意图。正常品牌比较、购买渠道说明或售后联系方式描述不成立。

### 7.6 涉政暴恐等敏感信息

结合完整语境存在政治攻击、宣传煽动、恐怖组织、严重血腥、极端主义等明显内容。仅出现国家、历史、军事等普通词语不成立。

### 7.7 低俗色情

存在明显性暗示、挑逗、裸露、性行为、色情交易或引流。正常医学描述、身体部位和商品使用场景不成立；涉及未成年人时优先选择“涉未成年人”。

### 7.8 毒品枪支等违禁品

真实涉及违禁商品、服务、交易、宣传或引流。影视讨论、新闻引用、比喻和无交易含义的提及不成立。

### 7.9 涉未成年人

包含针对未成年人的低俗、有害、隐私、色情、暴力或诱导内容。“给孩子买、小朋友喜欢、学生使用、儿童耳机”等正常表达不成立。

### 7.10 利用中差评索取不当利益

只有评价原文本身明确表达以差评、删改评价或追加差评为条件索取订单外利益时才可自动选择。由于本方案不授权平台查看聊天记录，也不上传聊天凭证，仅凭系统内部聊天推断不得自动投诉；原文不直接支持时返回`no_complaint`并正常回复。

### 7.11 未收到货但给出与商品实际不符的虚假评价

必须同时满足：当前页面可核对评价时间早于签收时间或评价时订单明确未收货；评价却描述具体使用体验或实际商品问题。评价物流慢、未发货、未送到或客服不处理物流不成立。

### 7.12 评价使用虚假或网络图片

只有平台评价图片和当前页面信息足以明确显示图片与评价内容无关或来源异常时才可选择。单凭“看起来像网图”、图片风格、清晰度或AI猜测不得投诉；无法确定时正常回复。

### 7.13 同行恶意中差评

只有评价原文或当前平台页面已存在可核对的同行身份和明确恶意行为时才可选择。专业措辞、中差评、无图、低账号等级、语气强烈或购买数量多均不能单独证明同行恶意。

## 8. 类型冲突与唯一选择

按以下顺序处理重叠场景，但只有当前类型自身条件成立时才具有优先权：

1. 涉未成年人；
2. 涉政暴恐；
3. 违禁品；
4. 低俗色情；
5. 隐私泄露；
6. 索取不当利益；
7. 同行恶意评价；
8. 未收货虚假评价；
9. 虚假或网络图片；
10. 广告；
11. 购买A评价B；
12. 辱骂侮辱；
13. 无意义。

补充规则：

- 联系方式用于引流选广告，用于公开他人信息选隐私；
- 明确涉及未成年人隐私或色情时选涉未成年人；
- 真实违禁品交易或宣传优先于普通广告；
- 有明确其他商品语义时选购买A评价B，不选无意义；
- 多个类型都无法确定时不猜测，返回`no_complaint`并正常回复。

## 9. 投诉描述唯一格式

因为不上传投诉凭证，描述中不得出现“所附凭证”“已上传凭证”“聊天记录证明”等与实际操作不一致的文字。

固定格式：

```text
该评价内容为“{评价原文或关键原句}”。经核对，{与所选投诉类型对应、且可由评价原文或当前页面事实核对的客观说明}，符合“{官方投诉类型名称}”场景。请平台结合评价内容及相关信息审核，并屏蔽处理，谢谢。
```

生成规则：

1. 短评使用完整原文；长评使用最直接支持投诉的连续关键原句；隐私投诉只使用带占位符的脱敏连续原句；
2. 客观说明只能由版本化`factCode`映射生成，不能直接采用AI自由文本；
3. 不得编造物流、聊天、图片来源、同行关系或买家动机；
4. 隐私投诉使用脱敏表述，不在描述中重复具体隐私；
5. 描述必须与页面实际选择的官方类型完全一致；
6. 长度为1～1000个字符；超长时优先保留原句、核心说明、官方类型和固定结尾；
7. 写入描述框后必须回读并逐字校验。

示例：

```text
该评价内容为“111111111111”。经核对，该内容与本订单商品、物流及商家服务均无实际关联，符合“评价内容无意义”场景。请平台结合评价内容及相关信息审核，并屏蔽处理，谢谢。
```

```text
该评价内容为“使用后质量很差”。经核对，该评价发布时订单尚未签收，但评价描述了具体商品使用体验，符合“未收到货但给出与商品实际不符的虚假评价”场景。请平台结合评价内容及相关信息审核，并屏蔽处理，谢谢。
```

## 10. 页面操作与元素边界

投诉流程只注册和操作：

- 评价的“投诉”入口；
- 官方投诉类型选项；
- 投诉弹窗；
- 投诉描述文本框；
- 提交按钮；
- 提交成功标识；
- 平台案件编号或可再次打开的投诉详情入口；
- 投诉结果状态。

以下可选项只注册为只读安全哨兵，提交驱动没有点击、勾选、上传或修改它们的能力：

- “授权小二查看近90天旺旺聊天记录”复选框；
- “投诉凭证”添加/上传区域；
- 上传文件输入框。

只读哨兵仅读取复选框`checked`状态和附件数量。若平台默认勾选、页面残留附件或无法可靠读取，当前投诉停止并提示人工清空；系统不会尝试代替用户修改。这一检查不在产品界面暴露为配置，也不恢复任何旺旺授权或凭证上传功能。

提交前必须全部满足：

- 当前店铺与配置店铺一致；
- 当前评价ID、商品和数据库记录一致；
- 从当前评价行重新读取主评/追评阶段、规范化正文和图片哈希，按案件冻结的`ReviewContentCanonicalizer`版本重算`analysisTextHash`并完全一致；不一致时废弃`prepared`结果并在保留投诉审核锁的情况下重新分析；
- 评价仍未回复、仍可投诉且平台不存在已提交案件；
- 投诉类型、描述框和提交按钮均唯一匹配；
- 页面选择的类型与案件类型一致；
- 描述回读与程序生成内容逐字一致；
- 旺旺授权保持未勾选，凭证列表保持为空；
- 没有验证码、安全验证、处罚、退款或其他禁止自动操作的弹窗。

投诉类型、描述框和提交按钮属于高风险元素。定位版本首次建立或变更后须由用户批准一次；批准后每条正常案件无需人工确认。投诉元素失效只暂停投诉候选，不影响已经判断为“不投诉”的评价继续正常回复；错店铺、验证码或账号安全问题则暂停整个自动化。

## 11. 投诉与回复的原子互斥

数据库建立`review_action_locks`，以`storeId + sourceKey`唯一约束一条评价的外部动作：

- `actionKind`只允许`complaint`或`reply`；
- 读取到新评价后，系统必须先在SQLite `BEGIN IMMEDIATE`事务中创建案件并取得`complaint`审核锁，再进入`discovered/analyzing`；未取得锁不能开始AI分析；
- 投诉和回复均必须以`lockVersion`条件更新和比较并交换方式取得或转换动作锁；
- 已处于投诉`discovered/analyzing/prepared/submitting/submitted/under_review/upheld/submission_uncertain/retry_wait/failed`的评价不能取得回复锁；
- 已处于回复`submitting/sent/submission_uncertain`的评价不能取得投诉锁；
- `no_complaint`和`rejected`只有在确认评价仍未回复且可回复后，才能在同一事务中把案件状态和动作锁从`complaint`转换为`reply`；
- `no_complaint`或`rejected`时若平台确认评价已过回复期限、已回复或不可再操作，则在同一事务中转`not_actionable`并压缩为终态墓碑；
- `closed`不能自动转换为回复，必须先核实关闭原因和评价可回复状态；
- `submission_uncertain`永久保留当前动作锁，直到平台核对完成；
- `complaint_attempts`对`caseId`建立活动attempt唯一约束；同一案件不能同时存在两个活动提交尝试；
- 手动触发、定时触发、重启恢复和重新分析都必须使用同一动作锁，不能依赖控制器调用顺序。

## 12. 状态机、提交检查点与恢复

投诉状态：

- `discovered`：待分析；
- `analyzing`：AI分析中；
- `no_complaint`：不投诉，转正常回复；
- `prepared`：类型和描述已冻结；
- `submitting`：已保存点击前检查点；
- `submitted`：平台已确认收到并取得稳定案件标识；
- `under_review`：平台审核中；
- `upheld`：投诉成立或评价已屏蔽；
- `rejected`：投诉不成立；
- `closed`：平台关闭、撤回或失效；
- `not_actionable`：评价已过操作期限、已回复或平台明确不可再处理；
- `submission_uncertain`：无法确认平台是否收到；
- `retry_wait`：仅限点击前的技术错误等待；
- `failed`：需要处理的配置或技术错误。

每次提交创建不可变`attemptId`并依次持久化：

1. `intentSavedAt`：类型、描述、店铺和评价已冻结；
2. `clickStartedAt`：准备点击提交，事务提交后才能点击；
3. `clickFinishedAt`：浏览器完成点击；
4. `platformCaseId/detailUrl`：平台确认受理后的稳定标识；
5. `resultObservedAt`：最后一次读取投诉结果。

点击提交后发生超时、断网、崩溃或响应丢失，一律进入`submission_uncertain`，不得自动再次点击，也不得转去回复。服务重启时，任何遗留`submitting`都先通过平台投诉记录、案件ID或详情入口核对；无法证明未提交时仍按`submission_uncertain`处理。

正式启用自动投诉前，预检必须确认平台能提供稳定案件ID或可再次打开的投诉详情入口；当前页面版本无法做到时，自动提交保持关闭。

平台结果映射采用版本化枚举：

- “审核中/处理中” → `under_review`；
- “投诉成立/评价已屏蔽/处理成功” → `upheld`；
- “投诉不成立/审核未通过/处理失败” → `rejected`；
- “已关闭/已撤回/已失效” → `closed`；
- 未知新状态 → `submission_uncertain`，不自动回复。

各状态的锁和恢复规则：

| 状态 | 保留投诉锁 | 允许自动回复 | 重启恢复 |
| --- | --- | --- | --- |
| `discovered` | 是 | 否 | 继续分析或按重试策略进入`retry_wait` |
| `analyzing` | 是 | 否 | 视为中断，重新执行纯分析，不执行外部提交 |
| `no_complaint` | 否，事务内转回复锁 | 是 | 从回复锁继续正常流程 |
| `prepared` | 是 | 否 | 使用冻结版本重新做页面预检 |
| `submitting` | 是 | 否 | 先查平台；无法确认则`submission_uncertain` |
| `submitted/under_review` | 是 | 否 | 只轮询结果，不再次提交 |
| `upheld` | 否，事务内压缩为终态墓碑 | 否 | 不再操作该评价 |
| `rejected` | 否，满足条件后事务内转回复锁 | 是 | 先确认评价仍可回复，再转换 |
| `closed` | 是 | 否 | 进入人工核对，不能自动视为拒绝 |
| `not_actionable` | 否，事务内压缩为终态墓碑 | 否 | 不再操作该评价 |
| `submission_uncertain` | 是 | 否 | 继续核对，不自动释放 |
| `retry_wait` | 是 | 否 | 到期后只重试点击前步骤 |
| `failed` | 是 | 否 | 等待配置恢复或人工处理，不自动释放 |

`submission_uncertain`和`closed`提供受审计的人工核对闭环，仅允许三种结论：

- “确认投诉成立/平台已收到”：必须记录平台案件ID、明确状态或经白名单归一化的详情路径；已收到转`submitted/under_review`，已成立转`upheld`；
- “确认投诉不成立/平台未收到”：必须二次确认并记录当前平台投诉记录页的脱敏核对快照；投诉不成立转`rejected`，平台未收到回到`prepared`，但均不在本次操作中直接提交或回复；
- “仍无法确认”：保持`submission_uncertain/closed`和动作锁不变。

`no_complaint/rejected`随后统一核对评价可操作性：仍可回复才原子转回复锁；已过期限、已回复或不可操作则转`not_actionable`墓碑；无法读取状态则保留投诉锁并进入`failed`，不得猜测。

人工核对不提供“再次提交”按钮，所有后续提交仍只能由自动控制器重新预检后执行。

## 13. 数据模型与版本

新增：

- `complaint_cases`：`sourceKey`、评价ID、主评/追评阶段、决策、类型、`factCode`、脱敏原句、描述、`analysisTextHash`、正文规范化版本、冻结图片清单、批准视觉结果引用、状态、平台结果、创建/更新时间；
- `complaint_attempts`：不可变`attemptId`、点击检查点、平台案件ID、归一化详情路径、`resultObservation`和错误类型；
- `complaint_events`：脱敏状态变化与操作审计；
- `review_action_locks`：投诉/回复互斥动作锁。
- `review_action_tombstones`：终态最小幂等记录，只含`storeId`、`sourceKey`、`terminalAction`和`completedAt`。

每个案件冻结：

- `analysisTextHash`；
- `reviewContentCanonicalizerVersion`；
- `reviewPhase`（主评/追评）；
- 按页面顺序排列的`imageId + imageHash`冻结清单；
- `factCode`；
- 图片内容类投诉使用的脱敏视觉标签、主/复核分析器版本及其绑定`reviewId + imageId + imageHash`；
- `promptVersion`；
- `ruleVersion`；
- `factMappingVersion`；
- `descriptionBuilderVersion`；
- `platformOptionMapVersion`；
- 模型名称。

官方中文类型名称和页面选项映射由程序版本化维护，不接受AI自由文本。已进入`prepared`的案件继续使用冻结版本，规则更新不能静默改变待提交案件。

冻结视觉结果不保存评价原图，仅保存脱敏标签、分析器版本、绑定标识和哈希；服务重启后能够验证旧结果属于同一评价图片，但不能从数据库还原或外传图片内容。

平台详情地址不得原样持久化。只保存平台案件ID，或保存经`https://myseller.taobao.com`/当前已批准千牛域名白名单校验、移除查询参数和片段后的相对路径；任何临时令牌、追踪参数和认证信息必须丢弃。

不保存账号密码、Cookie、验证码、完整登录页面、旺旺聊天记录、投诉图片或本地上传文件。评价原文的脱敏副本、AI结果和投诉描述保留90天；脱敏状态事件、提交attempt、平台案件ID和结果保留180天；脱敏页面快照保留7天。活动案件、`submission_uncertain`案件和活动动作锁在普通清理中受保护。隐私案件从不持久化原始号码、地址、证件或账户信息。

`upheld`、`not_actionable`、已完成回复等终态不永久保留完整动作锁：终态事务将活动锁压缩为`review_action_tombstones`。墓碑保留180天；到期且平台确认评价已不可操作或连续两次完整扫描均不再出现该评价时删除。活动、`submission_uncertain`、`closed`和`failed`锁不得压缩或过期删除。

## 14. 频率、故障与熔断

- 同一店铺同时只允许一个投诉提交；
- 两次投诉提交开始时间至少间隔15秒，这是平台保护节流，不是业务数量上限；
- 点击前网络错误可按5秒、15秒最多重试2次；
- 点击后任何网络错误都进入`submission_uncertain`；
- 10分钟内连续3次投诉页面、元素或合同错误，暂停投诉子系统；
- 投诉子系统暂停时，已明确为`no_complaint`的评价仍可正常回复；
- 店铺身份错误、验证码或账号安全验证进入全局`manual_action_required`。

## 15. API与正式界面

只有内部自动控制器能够调用投诉提交服务，不提供任意评价的公开直接投诉API。

案件接口：

- `GET /api/complaints`
- `GET /api/complaints/:id`
- `GET /api/complaints/status-summary`
- `POST /api/complaints/:id/recheck`：只允许重新分析未提交且未占用回复锁的案件，不直接绕过队列提交。
- `POST /api/complaints/:id/reconcile`：仅处理`submission_uncertain/closed`的人工核对结果，要求当前会话、二次确认、操作审计和平台核对记录；不直接提交投诉。

正式界面增加“投诉记录”，显示：评价原文、官方投诉类型、投诉描述、状态、提交时间和平台结果。界面不显示提示词JSON、内部`factCode`、HTTP状态码或原始异常。

工作台显示本轮：投诉候选、已提交、审核中、投诉成立、投诉不成立和结果待核对。结果待核对必须醒目标记，并说明该评价不会重复投诉或回复。

界面不提供旺旺授权和凭证上传配置，因为自动化明确不使用这两个功能。

## 16. 测试方案

### 16.1 规则和提示词

- 13种类型各覆盖明确命中、明确不命中和重叠类型；
- 普通真实好评/差评不被错误投诉；
- “好、不错、一般、还行、不好用、已收到”不被判无意义；
- 商品负面词不被判成人身辱骂；
- A商品评价提到B品牌但仍评价A时不误判购买A评价B；
- 正常退款、换货、补发不被判索取不当利益；
- 提示词注入、非法类型、额外字段、伪造原句和非法`factCode`被拒绝；
- `FactCodeRegistry`的13种类型分别验证必需字段、排除条件和唯一固定说明；
- 主分析与独立验证不一致时返回`no_complaint`；
- 无可信图片来源信号时“虚假或网络图片”返回`no_complaint`；
- 无评价原文自认同行和恶意表达时“同行恶意评价”返回`no_complaint`；
- 隐私等长脱敏、Unicode码点区间和内存区间映射在中文、emoji、手机号混排时均正确；
- 隐私原文不会进入AI输入、投诉描述、数据库或日志。
- PII存在但归属为买家本人、公开经营信息或未知时不投诉；只有明确第三方归属才允许隐私投诉；
- 图片文字描述或OCR单独命中不能授权投诉；图片哈希绑定的双视觉结果一致时才可命中图片内容类投诉；

### 16.2 页面操作

- 投诉类型选择正确且唯一；
- 只填写投诉描述并逐字回读；
- 旺旺授权始终未勾选；
- 投诉凭证始终为空且上传控件从未被触发；
- 只读安全哨兵发现默认勾选、残留附件或状态不可读时阻止提交，且不会自动修改页面；
- 描述中不出现“所附凭证”“已上传凭证”或“聊天记录证明”；
- 提交前评价正文、主评/追评阶段或图片任一变化都会导致内容哈希不一致、废弃旧`prepared`结果并重新分析；
- 错店铺、错评价、类型不一致、描述不一致和危险弹窗全部阻止提交。

### 16.3 幂等与故障恢复

- 从`discovered/analyzing`开始，投诉与回复并发竞争时只有投诉审核锁或既有回复锁之一成功；
- `no_complaint/rejected`的状态变更与投诉锁转回复锁在一个事务中完成；
- 每个案件的活动attempt唯一约束在并发和重启下均成立；
- 手动运行、定时运行、服务重启和重新分析不会重复提交；
- 服务重启后从案件快照恢复正文规范化版本、正文哈希、主评/追评阶段、图片哈希、`factCode`和视觉结果版本，并能完成同样的提交前校验；
- 点击前失败可受控重试，点击后响应丢失进入不确定状态；
- 在点击后、案件ID写入前模拟进程崩溃，重启后先核对且不再次点击；
- 无稳定案件ID/详情入口时预检禁止开启自动投诉；
- 平台各中文状态正确映射，未知状态不自动回复；
- `closed/retry_wait/failed/submission_uncertain`分别按状态矩阵保留锁并正确恢复；
- 结果不确定或平台关闭的“成立/已收到、不成立/未收到、仍无法确认”人工核对均要求二次确认和审计，且没有直接重提入口；
- `no_complaint/rejected`遇到已过回复期、已回复或不可操作评价时转`not_actionable`墓碑，不会永久占用活动锁；
- 含认证查询参数的详情URL只保存白名单归一化相对路径；
- 90天内容数据、180天提交审计和7天快照分别清理，活动及不确定案件受保护；
- 完成终态的活动锁压缩为180天最小墓碑，到期且评价不可操作后可清理；活动和不确定锁不会被误删；
- 投诉不成立后以原子事务转入回复，投诉成立后永不回复。

### 16.4 端到端

- 无意义评价：选择类型、填写固定描述、保持可选项为空并提交；
- 未收货虚假评价：核对评价时间和订单状态后生成描述并提交；
- 普通好评和真实差评：跳过投诉并继续自动回复；
- 投诉成立：评价不再回复；
- 投诉不成立：评价仍可回复时进入现有好评/差评流程；
- 提交结果不确定：不重提、不回复并展示待核对状态。

## 17. 验收标准

1. 投诉弹窗中系统只填写“投诉描述”，旺旺授权始终不勾选，投诉凭证始终不上传；
2. AI只能在13种官方类型中选择，无法确定时不投诉并继续自动回复；
3. 投诉描述严格使用固定格式，不包含虚构事实或未上传凭证的表述；
