# 自定义 Chrome 路径设计

## 目标

评论助手优先自动识别标准安装的 Google Chrome；自动识别失败时，用户可以在设置页选择任意位置的 `chrome.exe`。程序验证所选浏览器确实能够启动后再保存，后续登录、评论回复和投诉流程统一使用该路径。

## 用户流程

1. 程序检查已保存的自定义路径；有效时优先使用。
2. 自定义路径无效时，检查当前 Windows 账户和 Program Files 下的标准 Chrome。
3. 都找不到时，设置页显示“未找到可用 Chrome”和“选择 Chrome”按钮。
4. 点击按钮打开 Windows 文件选择窗口，只允许选择 `chrome.exe`。
5. 后端使用独立临时资料目录启动并关闭所选 Chrome；验证成功才保存路径。
6. 保存后关闭旧的淘宝浏览器上下文，下一次验证登录时使用新路径。
7. 自定义路径移动、删除或换电脑后失效时，程序回退到标准识别；仍找不到则提示重新选择。
8. 用户可点击“恢复自动识别”清除自定义路径。

## 组件

- `tmall/browser-executable.ts`：验证路径、查找标准安装、决定实际使用路径。
- `tmall/local-chrome-picker.ts`：调用 Windows 原生文件选择窗口并解析结果。
- `resources/select-local-chrome.ps1`：仅选择现有的 `chrome.exe`。
- `tmall/browser-runtime.ts`：支持显式 `executablePath`，没有自定义路径时继续使用 `channel: "chrome"`。
- `tmall/auth-driver.ts`：每次创建浏览器上下文时读取当前有效路径。
- `app.ts`：提供浏览器状态、选择验证、恢复自动识别接口，并将路径保存到数据库设置。
- `settings.tsx`：显示识别来源、路径状态和选择按钮。

## 数据与安全

- Chrome 路径不是凭据，存放在 SQLite `settings` 中。
- 不允许控制字符、目录路径、非 `.exe` 文件或文件名不是 `chrome.exe` 的路径。
- 文件选择取消不修改现有设置。
- 验证失败不保存候选路径，接口只返回可读的安全错误。
- 自动回复运行中禁止切换浏览器，避免正在提交评价时关闭上下文。
- 发布包不携带该电脑的浏览器资料；换电脑后无效路径会自动降级。

## 验证

- 单元测试覆盖标准识别、自定义优先、失效回退和非法路径。
- 文件选择器测试覆盖选择、取消、进程失败和关闭。
- API 测试覆盖状态、验证后保存、验证失败不保存、运行中拒绝切换和清除路径。
- 浏览器运行测试覆盖显式 `executablePath` 与默认 `channel`。
- 设置页测试覆盖缺少 Chrome、选择成功、自定义路径展示和恢复自动识别。
- 执行全量测试、类型检查、构建，并生成保留数据库但不携带浏览器资料的新发布包。
