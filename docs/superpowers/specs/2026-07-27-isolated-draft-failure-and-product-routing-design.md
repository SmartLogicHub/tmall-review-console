# 单条草稿故障隔离与商品兼容路由设计

## 目标

1. 单条评价在草稿生成阶段出现未知异常时，只结束当前条并继续页面中的下一条，不得把整轮升级为“需要人工处理”。
2. 页面下一轮仍明确显示回复入口时，允许现有安全重开机制重新处理该条失败记录。
3. 保留安全、可定位的失败阶段，避免再次只留下无法判断来源的 `DRAFT_PROCESSING_FAILED`。
4. 分类模型直接选择了与当前商品族不兼容的专属分类时，代码必须拦截并重新选择兼容分类或兜底分类。

## 故障隔离

- `DRAFT_PROCESSING_FAILED` 表示当前评价的本地草稿生成失败，不是登录、验证码、永久性 AI 配置或提交结果不确定。
- 草稿处理器返回新的“当前条失败并继续”结果。
- 自动运行将失败计入本轮 `failed`，显示“当前评价草稿生成失败，已继续下一条”，但不改变全局运行状态。
- 队列沿用当前 `seen` 集合，避免同一轮立即循环重试；下一轮页面仍有回复入口时，由 `reopenObservedLiveAction` 安全重开。
- API Key 无效、余额不足、验证码以及提交后结果不确定等既有全局保护边界保持不变。

## 错误阶段

草稿生成过程维护安全阶段标签：

- 商品人工策略判断；
- 话术目录读取；
- 评价分类；
- 投诉资格核对；
- 话术选择；
- 分类与话术检查点保存；
- 商品信息修正与最终草稿保存。

未知异常只保存阶段描述，不保存 DeepSeek 原始响应、密钥、页面内容或堆栈。

## 商品兼容路由

- 商品族由当前商品名称识别：耳机、音箱、扩音器、麦克风或未知。
- 分类的一级分类、分类名和关键词共同构成分类语义。
- 模型直接返回的分类若明确提及另一商品族，则不得采用。
- 不兼容分类先回到对应情感库的兜底分类，再使用既有确定性维度和关键词匹配寻找兼容的具体分类；没有可靠候选时保留兜底。
- 话术选择阶段继续执行商品兼容过滤，形成分类和话术两层保护。

## 本次真实样本期望

1. `漫步者H180Plus ... 耳机` 的“k歌不行、收不进高音、耳返延迟”属于普通差评，不投诉；不能选择带“小蜜蜂扩音器”语义的话术。目录没有耳机 K 歌专属分类时，应选择兼容的音质问题分类或通用差评。
2. `漫步者 atomdot ... 耳机` 的“骑车风声被放大、听书听不清，室内还好”属于普通差评，不投诉；应优先选择“降噪体验 / 环境音”。

## 验证

- 先写失败测试，证明未知草稿异常会停止整轮。
- 修复后验证第一条失败、第二条仍完成提交，运行以 `queue_empty` 正常结束。
- 验证失败记录下一轮在页面仍可回复时会安全重开。
- 验证耳机不会采用扩音器专属分类，扩音器本身仍可采用该分类。
- 验证风噪追评选择“环境音”。
- 运行服务端全量测试、类型检查、项目全量测试和生产构建。
