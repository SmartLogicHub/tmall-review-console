# 天猫评论智能处理控制台公开 GitHub 发布设计

## 目标

将当前项目整理为可公开访问的 GitHub 源码仓库，完整展示项目能力和控制台界面，同时确保真实业务数据、登录状态、密钥、日志、诊断信息和本地发布包不会进入 Git 历史。

## 发布方式

采用“源码公开、运行数据隔离、安装包单独发布”的方式：

- GitHub 仓库公开完整源代码、测试、技术文档和脱敏截图。
- 仓库不包含任何运行数据库、浏览器资料、日志、备份、诊断文件或现有本地发布目录。
- Windows 便携包如果需要公开下载，只能通过不含本地状态的打包模式重新生成，并作为 GitHub Release 附件发布。
- 当前 `release-final-20260726-v7` 含数据库和浏览器资料，只供本地使用，禁止上传。

## 仓库内容边界

公开内容：

- `apps/web`：React 控制台。
- `apps/server`：Fastify 服务、SQLite 存储、AI 分类和浏览器自动化流程。
- `apps/launcher`：Windows 启动器源码。
- `packages/domain`：领域模型、规则与状态机。
- `tests`：端到端测试。
- `scripts`：开发、数据修复和无本地状态打包脚本。
- `docs`：设计文档和脱敏展示图片。
- `README.md`、开源许可证和 GitHub Actions 配置。

禁止公开：

- `data/`、任何 `*.sqlite*` 文件。
- 浏览器 profile、Cookies、登录数据和本地存储。
- `.state-backups/`、`migration-backups/`、`.diagnostics/`。
- `.pnpm-store/`、`.runtime/`、`node_modules/`。
- `release-final-*`、`*.zip` 和其他本地发布产物。
- 日志、测试运行产物、真实表格、工作汇报和临时修正数据库。
- `.env*`、API Key、App Secret、账号密码、真实飞书地址和真实订单信息。

## README 展示

README 使用正常 UTF-8 中文，首屏快速说明项目用途、安全边界和主要能力。正文包含：

1. 项目简介与安全提示。
2. 三张控制台截图。
3. 核心功能。
4. 技术架构。
5. 本地开发与测试命令。
6. Windows 干净包的构建方式。
7. 配置说明。
8. 数据与凭据安全说明。
9. 开源许可证。

截图固定为：

- `docs/images/console-overview.png`：工作台/控制台首页。
- `docs/images/run-center.png`：自动处理中心。
- `docs/images/reply-results.png`：回复结果、状态筛选和清理按钮。

## 截图脱敏

截图使用独立演示数据库和虚构内容生成，不读取正式 `data`：

- 店铺、买家、订单号、商品和评论全部为虚构示例。
- 不展示 API Key、密码、飞书 App Secret 或完整飞书地址。
- 不展示真实浏览器 profile、历史回复和投诉记录。
- 不连接天猫，不提交回复或投诉。
- 截图生成后检查画面文字，再放入 `docs/images/`。

## GitHub Actions

基础 CI 在 push 和 pull request 时运行：

- 安装锁定依赖。
- 运行领域、服务端和前端测试。
- 运行 TypeScript 类型检查。
- 运行生产构建。

Windows 凭据管理器相关的非交互测试在 CI 中按现有测试条件跳过或使用内存替代，不接触真实系统凭据。

## 许可证

使用 MIT License，允许使用、修改和再发布，同时保留版权与许可证声明。

## 发布前验证

公开上传前必须完成：

1. `git status` 中不出现运行数据、浏览器资料、备份或发布包。
2. Git 已跟踪文件中不存在数据库、ZIP、日志、真实截图或凭据。
3. README 图片均为脱敏演示图。
4. 测试、类型检查和生产构建通过。
5. 运行敏感信息扫描，只报告文件位置，不输出疑似密钥内容。
6. 确认 GitHub 仓库名称、说明和公开可见性后，才创建远程仓库并推送。

## 外部操作边界

本地整理、截图、测试、提交可以在本项目内完成。创建公开 GitHub 仓库和首次推送属于外部公开操作，执行前再次向用户确认仓库名称和最终公开内容。
