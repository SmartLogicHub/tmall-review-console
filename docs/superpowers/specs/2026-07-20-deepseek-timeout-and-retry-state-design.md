# DeepSeek 超时与待重试状态设计

## 目标

统一延长所有 DeepSeek 请求的等待时间，避免另一台电脑上正常但较慢的请求在 10 秒时被取消；同时让投诉预审失败进入可恢复的待重试状态，并让界面只展示数据库中的真实处理阶段。

## 已确认方案

- 所有 DeepSeek 请求共用 60 秒单次超时。
- 保留现有的一次自动重试，单条请求不会无限挂起。
- 投诉预审的超时、网络和模型格式错误同步写入回复草稿的待重试字段，下一轮能够恢复。
- 回复详情根据 `discovered`、`retry_wait`、`submitting`、`sent` 等真实状态显示，不再把未分类记录称为“回复已生成”。
- 本次修改后执行针对性测试、全量测试、类型检查、构建和含本地数据的 Windows 打包。

## 不改变

- 投诉仍采用独立二审和硬校验。
- 已发送记录、提交不确定保护和人工商品跳过策略保持不变。
- 不采用无限等待，避免单个请求永久卡死整轮任务。
