# 淘宝商家登录恢复与弹窗白名单设计

## 1. 目的与覆盖关系

本规格为《天猫评论智能自动回复控制台设计》的补充规格，解决两个已经在真实商家页面验证的问题：

1. 应用专属 Chromium 的持久化登录态仍可能过期，系统需要在用户授权后使用保存的商家凭据自动重新登录；
2. 商家后台会出现遮挡分页、筛选或后续回复区域的浮层和引导弹窗，自动化必须安全关闭已确认的无风险弹窗。

本规格覆盖主规格中“控制台不保存淘宝账号密码、登录只能人工完成”的旧约束。第一阶段“禁止真实提交评论回复”的安全边界保持不变：自动登录可以操作认证页面，但不能获得评论输入、回复提交或任意页面脚本执行能力。

## 2. 核心原则

- 优先复用应用专属 Chromium 用户目录中的现有登录态，不为每次运行重复登录。
- 只有用户在 Web 控制台明确保存凭据并开启“登录失效时自动重登”后，系统才允许自动登录。
- 淘宝账号和密码只保存到当前 Windows 用户的 Credential Manager，不写入 SQLite、配置文件、浏览器 Local Storage、日志、审计或导出。
- 登录、只读评论处理和未来的真实回复提交是三个能力隔离的运行模式。第一阶段不存在真实回复提交模式。
- 验证码、短信验证、扫码确认、设备安全校验和账号风险提示不得绕过；出现时暂停并交给用户处理。
- 仅自动关闭白名单中的无风险弹窗。未知弹窗、确认类弹窗和安全类弹窗一律暂停，不由 AI 自主关闭。
- 每次自动登录后必须验证店铺身份、评价管理页面和筛选状态，不能只凭 Cookie、URL 或登录按钮消失就认定成功。

## 3. Web 界面

### 3.1 系统设置：淘宝商家登录

在“系统设置”页面顶部增加“淘宝商家登录”卡片，包含：

- 账号输入框；保存后只显示脱敏账号，例如首尾各保留一个字符，其余使用 `*`；输入控件禁用浏览器自动完成，不写入前端持久化存储；
- 密码输入框，始终使用密码类型、声明为新凭据输入、禁用浏览器自动完成且保存后保持空白，不提供显示旧密码或复制旧密码的能力；表单不执行浏览器原生提交；
- “保存并测试登录”主按钮；
- “立即重新登录”按钮，仅在已配置凭据且任务停止或暂停时可用；
- “清除自动登录凭据”按钮，二次确认后仅删除 Credential Manager 中的淘宝凭据，保留当前浏览器登录态；
- “退出并清除全部登录数据”危险按钮，停止任务并二次确认后关闭应用浏览器，删除淘宝凭据和应用专属 Chromium 用户目录；
- “登录失效时自动重登”开关，默认在用户首次保存并测试成功后开启，用户可随时关闭；
- 最近一次登录时间、最近一次会话检查时间、最近一次失败原因和当前店铺身份。

界面状态使用以下有限集合：

| 状态 | 含义 | 可用操作 |
|---|---|---|
| `not_configured` | 未保存自动登录凭据 | 保存并测试登录、人工打开登录页 |
| `checking_session` | 正在验证持久化登录态 | 取消检查 |
| `authenticated` | 已登录且店铺身份匹配 | 立即重新验证、清除凭据 |
| `session_expired` | 已确认登录失效 | 自动重登或人工登录 |
| `auto_signing_in` | 正在使用保存凭据登录 | 取消并转人工处理 |
| `manual_verification_required` | 验证码、短信、扫码或安全校验 | 打开登录浏览器、我已完成验证 |
| `manual_action_required` | 新手引导、未知弹窗或其他页面需要用户处理 | 在已打开窗口处理、我已完成并继续检测 |
| `not_ready` | 登录页尚未完成跳转且没有明确凭据错误 | 继续在已打开窗口操作、重新检测 |
| `navigation_failed` | 已登录但暂时无法安全进入评价管理 | 处理当前页面、重新检测 |
| `credential_rejected` | 页面明确提示账号或密码错误 | 修改凭据或立即重新尝试 |
| `identity_mismatch` | 登录后的店铺与已绑定店铺不一致 | 退出并人工切换账号 |
| `credential_error` | 凭据读取、保存或删除失败 | 重试、查看脱敏错误 |

### 3.2 运行中心

- “服务健康”中的天猫状态灯使用上述登录状态，不把“浏览器进程存在”显示成“已登录”。
- 登录失效时立即暂停新评论读取，并显示常驻顶部横幅：失效时间、自动重登状态、失败原因以及“打开浏览器处理”。
- 自动登录成功后显示店铺身份验证结果、弹窗清理结果和恢复的流程位置。
- 弹窗处理只显示 `popupKey`、结果和时间，不显示通知正文、订单号或买家信息。

## 4. 凭据存储与接口

### 4.1 Windows Credential Manager

- 使用一个固定目标名，例如 `TmallReviewConsole/TaobaoSeller`，以 Credential Manager 的用户名字段保存账号、秘密字段保存密码。
- SQLite 只保存 `configured`、`updatedAt`、`autoReloginEnabled`、脱敏账号和凭据引用名，不保存原账号或密码。
- 服务启动时只读取“是否已配置”，需要自动登录时才读取凭据；登录动作结束后立即释放应用层引用，不承诺 JavaScript 运行时无法保证的内存物理清零。
- 凭据绝不进入异常对象、遥测、网络审计、测试快照或崩溃报告。日志中对 `password`、`passwd`、`credential`、`cookie`、`token`、`authorization` 等字段执行拒绝记录而非事后替换。
- 第一阶段不提供凭据导出、回显、复制或远程同步。

### 4.2 本地接口

新增接口均绑定 `127.0.0.1`，不启用 CORS，并按风险分级校验：所有接口要求正确 Host 和会话 Cookie；读取接口不要求 CSRF 或 nonce；普通状态变更要求精确同源 Origin、`Sec-Fetch-Site: same-origin` 和 CSRF；凭据写入/删除及清除全部登录数据还要求5分钟有效的单次确认 nonce。响应统一使用 `Cache-Control: no-store`，凭据请求只接受限长 JSON 且在日志中禁用请求正文：

- `GET /api/tmall-auth/status`：只返回状态、脱敏账号、店铺身份和时间，不返回凭据；
- `POST /api/tmall-auth/confirmations`：在有效会话与 CSRF 下，为 `credential_upsert` 或 `credential_delete` 签发与当前会话、具体动作绑定的5分钟单次 nonce；不接受任意动作字符串；
- `PUT /api/tmall-auth/credential`：保存账号和密码并返回 `{configured, maskedAccount, updatedAt}`；
- `DELETE /api/tmall-auth/credential`：二次确认后删除凭据；
- `PUT /api/tmall-auth/settings`：使用 CSRF 更新 `autoReloginEnabled`，不读取或返回凭据；
- `POST /api/tmall-auth/test`：停止或暂停任务后执行一次保存并测试登录；
- `POST /api/tmall-auth/relogin`：手动触发自动重登；
- `POST /api/tmall-auth/manual-complete`：用户完成验证码或安全校验后触发重新验证；
- `POST /api/tmall-auth/clear-all/prepare|run`：签发单次 nonce，并删除凭据与应用浏览器目录。

`PUT` 只能消费绑定 `credential_upsert` 的 nonce，`DELETE` 只能消费绑定 `credential_delete` 的 nonce；nonce 使用后无论操作成功或失败都失效，不能跨会话、跨动作或重放。所有凭据新增、替换、删除、自动重登开关变化、清除全部登录数据和账号身份不匹配都写入180天操作审计。审计只记录动作、时间、结果、错误码和脱敏账号摘要。

## 5. 运行模式隔离

浏览器自动化包含三个互斥模式：

1. `automatic_read_only`：导航评价管理、选择“有内容”和“未回复”、读取评论及验证元素；不暴露账号密码填写能力，也不放行认证 POST；
2. `automatic_authentication`：任务必须已暂停，只能打开代码内固定的淘宝/天猫认证入口，只暴露账号填充、密码填充、登录按钮点击和认证状态读取；
3. `interactive_authentication`：打开可见浏览器供用户处理验证码、短信、扫码或安全校验，应用不模拟安全验证操作。

能力由三个不相互继承的受限驱动提供：

- `ReadOnlyTmallDriver` 不提供任何表单填充、通用点击或任意脚本执行；
- `AutomaticAuthenticationDriver` 只接受固定认证操作键，不接受任意 CSS/XPath、屏幕坐标、评论页定位键或弹窗键；
- `PopupDismissDriver` 只接受编译期白名单中的 `popupKey`，先在规则声明的弹窗作用域内完成多条件匹配，再执行该规则唯一的关闭动作。调用方不能传入定位器、按钮文字或坐标；登录按钮和所有评论回复操作键均不属于弹窗驱动命名空间。

模式切换规则：

- `automatic_read_only` 发现登录失效后先持久化当前评论处理断点并暂停任务，再关闭只读上下文；
- 只有自动重登已开启且凭据可读取时，才能进入 `automatic_authentication`；同一时刻只允许一个认证动作；
- 认证网络守卫仅放行代码内声明的认证主机、路径、方法和字段白名单；评论回复 API、回复表单 action、WebSocket 和未知请求在所有模式下继续永久阻断；
- 登录成功后关闭认证上下文，用同一应用专属用户目录重新启动 `automatic_read_only`；同一用户目录任何时刻只允许一个上下文占用；
- 第一阶段编译产物不包含评论回复填充、提交或通用 `evaluate` 接口。认证驱动的 `fill` 和 `click` 无法被只读驱动调用。

`automatic_authentication` 和 `interactive_authentication` 从模式进入到上下文彻底关闭的整个生命周期内，禁止截图、视频、DOM/可访问性快照、Playwright trace、控制台正文和响应正文取证，覆盖密码、二维码、短信验证码、设备确认和安全校验页面。需要记录失败证据时只保存错误码、URL 的规范化主机/路径和预定义页面状态枚举。

应用专属 Chromium 通过受管首选项和启动配置禁用密码保存提示、密码管理器、表单自动填充和关闭后标签页恢复；认证上下文关闭前导航到空白页并关闭全部认证标签，应用重启不恢复认证页面。前端收到凭据接口响应后立即清空输入框、表单状态和请求对象引用，不在 Local/Session Storage、IndexedDB、Service Worker、前端缓存或状态持久化插件中保存账号密码。

## 6. 会话检查与自动重登流程

### 6.1 登录态验证

每次应用启动、开始任务、恢复任务、开始新批次以及页面发生认证重定向后执行登录态检查：

- 明确出现淘宝登录表单、登录域名或认证重定向时，立即判定 `session_expired`；
- 同时验证商家后台的已登录标记、店铺标识和预期页面能力；仅缺少其中一个弱标记时，在3秒内复检两次，避免页面尚未加载完成造成误判；
- 首次成功绑定时记录稳定店铺标识和展示店铺名。后续登录必须匹配稳定标识；只有展示名可得时，不允许自动绑定变更，进入 `identity_mismatch`；
- 不使用买家昵称、订单号或商品标题推断店铺身份。

### 6.2 自动重登

1. 持久化当前运行断点并暂停新评论处理；
2. 检查自动重登开关、凭据状态和磁盘硬保护；
3. 进入 `automatic_authentication`，打开固定登录入口；
4. 先运行弹窗白名单检查，再填写账号和密码、点击唯一且语义匹配的登录按钮；
5. 等待认证重定向；出现验证码、短信、扫码、安全校验或候选登录按钮不唯一时立即进入 `manual_verification_required`；
6. 登录成功后重新启动只读模式，验证店铺身份；
7. 进入 `交易 → 评价管理 → 有内容 → 未回复`，关闭白名单弹窗并验证两个筛选项均为选中状态；
8. 用 `sourceKey` 重新定位中断记录，确认未产生重复 attempt 后继续。

登录不设置跨操作的冷却时间、次数锁或 `locked_out` 状态。只有页面明确显示账号或密码错误时才返回 `credential_rejected`；短信、电话、扫码、安全验证、新手引导、未知弹窗、页面尚未就绪和导航失败都不得描述为凭据错误。每次用户点击都视为一次新的有界操作，可立即重新尝试；同一时刻只允许一个认证动作，单次动作不在后台无限循环或重复提交。人工验证完成后的“继续检测”必须复用已打开的浏览器页和会话，不重新填写账号密码。旧版本保存的通用失败计数因缺少明确凭据拒绝证据，在启动或读取时清除且不得影响按钮状态。

## 7. 弹窗白名单管理器

### 7.1 处理策略

弹窗不能只在启动时检查。管理器在以下检查点运行：

- 登录提交前和登录成功后；
- 每次顶级页面导航和侧栏导航后；
- 点击“有内容”“未回复”、翻页及未来回复动作之前；
- 任一点击出现“被其他元素遮挡”时；
- 从人工验证模式返回自动模式时。

处理流程为：检测可见遮挡层 → 与白名单规则匹配 → 把固定 `popupKey` 交给 `PopupDismissDriver` → 在弹窗作用域内定位唯一关闭动作 → 执行一次 → 验证弹窗不可见且目标页面仍正确 → 重试原动作。单个弹窗最多关闭2次；同一弹窗反复出现或关闭后页面身份改变时暂停。

### 7.2 初始白名单

| `popupKey` | 多条件识别 | 允许动作 | 允许的新增网络副作用 | 关闭后验证 |
|---|---|---|---|---|
| `important_messages` | 可见区域同时包含“重要消息”和“预警通知”，并存在该浮层内的关闭控件 | 只点击浮层右上角关闭控件 | 无；关闭过程中新增的 POST/PUT/PATCH/DELETE/beacon 全部阻断 | 浮层不可见；评价列表或登录页身份不变 |
| `feature_upgrade` | 对话框标题为“功能升级”，按钮包含“关闭”或“我知道了” | 优先“关闭”，没有时使用“我知道了” | 无；关闭过程中新增的写请求全部阻断 | 对话框不可见；URL不变 |
| `new_user_guide` | 对话框标题为“新手引导”，存在“完成”按钮 | 点击“完成” | 无；关闭过程中新增的写请求全部阻断 | 对话框不可见；当前页面仍为已卖出宝贝或预期页面 |

规则必须同时使用语义文本、对话框/浮层作用域和相对关闭控件，不使用固定屏幕坐标，不点击页面上其他同名按钮。初始三个规则都不允许因关闭动作新增网络写权限；页面若依赖写请求才能完成关闭，则阻断该请求、把规则标为失败并暂停，不得为了让弹窗消失自动扩大网络白名单。未来确需允许副作用时，必须记录真实端点证据、按 `popupKey + 主机 + 路径 + 方法 + 字段` 精确声明、经过用户批准和独立测试；评论回复永久阻断清单仍拥有最高优先级。截图中右下角“重要消息”属于 `important_messages`，会遮挡底部分页；系统优先关闭后再操作分页。若底部分页仍受顶部固定栏遮挡，则优先使用页面上方同语义分页控件。

### 7.3 未知弹窗和 AI 修复边界

- 未匹配白名单的可见遮挡层进入 `unknown_popup`，暂停当前任务；
- 包含“验证码”“短信”“扫码”“安全”“风险”“确认提交”“删除”等验证或业务操作词的弹窗永久禁止自动关闭。根据 2026-07-16 的子账号使用决策，若“退款”“投诉”“处罚”只出现在已精确识别的 `important_messages`（同时具备“重要消息”“预警通知”和浮层内唯一右上角关闭控件）中，可以仅关闭该通知；不得点击“处理、确认、同意、拒绝、退款、申诉”等任何业务按钮。相同业务词出现在未知弹窗、表单或确认窗口中仍必须暂停；
- 元素健康模块可以为已知 `popupKey` 的关闭控件生成定位修复候选，但只能在原语义锚点仍存在、候选唯一、关闭后置条件可验证时自动启用；
- AI 不得把未知弹窗加入白名单，也不得选择“确认”“同意”“提交”“继续办理”等可能产生业务后果的按钮；
- 第一期只包含三个编译期 `popupKey`，Web 界面不提供运行时新增或批准弹窗类型的能力。用户可以在“元素健康”查看未知弹窗的脱敏结构，但只能暂停并等待后续代码版本增加新的编译期规则；新增 `popupKey` 必须经过代码审查、网络副作用声明和回归测试。运行时 AI 仅能修复这三个已知键内部的定位版本。

## 8. 数据生命周期与清除闭环

| 数据 | 保留时间 | 导出 | 清除方式 |
|---|---:|---|---|
| 淘宝自动登录凭据 | 直到用户清除或恢复出厂设置 | 永不导出 | 删除 Credential Manager 条目 |
| Chromium 登录目录 | 直到“退出并清除全部登录数据”或恢复出厂设置 | 不导出 | 关闭浏览器后校验专属路径并删除 |
| 登录尝试和状态事件 | 30天 | 脱敏 JSONL | 每日清理；不含账号原文和页面内容 |
| 凭据与登录安全审计 | 180天 | 脱敏 CSV | 按现有审计清理规则 |
| 弹窗处理运行日志 | 30天 | 脱敏 JSONL | 每日清理；只含 `popupKey` 和结果 |
| 弹窗定位版本 | 当前版和每个 `popupKey` 最近10版 | 脱敏 JSON | 新版生效后清除更旧历史 |

“清除运行记录”不删除淘宝凭据和 Chromium 登录目录；“清除自动登录凭据”不删除当前浏览器登录态；“退出并清除全部登录数据”和“恢复出厂设置”同时删除两者。每日自动清理永不删除仍在使用的凭据或浏览器登录目录。

“退出并清除全部登录数据”使用白名单临时目录中的 `tmall_auth_clear.intent` 实现可恢复清除。intent 只含随机操作ID、开始时间和以下分步状态：`task_stopped`、`browser_closed`、`credential_deleted`、`profile_deleted`、`finalized`。每步完成后原子更新；删除操作必须幂等。应用若在完成前崩溃，下次启动进入恢复模式，只允许继续未完成步骤，不启动浏览器、自动登录或评论任务；全部完成后写入一条脱敏审计并删除 intent。凭据已删但浏览器目录尚存、目录已删但审计未写等部分状态都必须可重试。

## 9. 异常与降级

- Credential Manager 不可用：不降级为明文保存，状态变为 `credential_error`，保留人工登录能力；
- 登录态失效但未配置凭据或自动重登已关闭：暂停任务并打开人工登录入口；
- 自动登录遇到验证码、安全验证或登录结构不唯一：进入 `manual_verification_required`，不调用 AI 绕过；
- 登录后的店铺身份不匹配：关闭自动处理，禁止读取该店铺评论，要求人工切换；
- 白名单弹窗关闭失败、重复出现或后置条件失败：暂停并进入元素健康事件；
- 未知弹窗：暂停；任何认证模式全生命周期都不截图或保存页面结构，其他页面只保存按既有规则脱敏的证据；
- 用户主动取消登录：保持任务暂停，不自动循环重启；
- 应用崩溃：凭据仍由 Credential Manager 管理；重启后先验证会话和上一次模式锁，绝不直接恢复到凭据已填充的页面。

## 10. 验收标准

### 10.1 界面与凭据

- 账号、密码、自动重登开关和四个登录操作在1366×768与1600×900下无遮挡；密码保存后不回显；
- 保存、替换、删除凭据后，SQLite、配置文件、日志、审计、导出、截图和错误响应中均不存在账号原文和密码；
- Credential Manager 保存失败时没有任何明文回退；
- 控制台前端刷新、关闭、崩溃和应用重启后，账号密码输入字段、Local/Session Storage、IndexedDB、Service Worker、前端状态缓存和 Chromium 密码数据库中均不存在账号密码原文；浏览器不显示保存密码提示，也不恢复认证标签页；
- “清除自动登录凭据”保留当前 Chromium 登录态；“退出并清除全部登录数据”删除凭据和专属浏览器目录，但不触碰日常 Chrome/Edge 配置；
- 读取接口在有效本地会话下可轮询且拒绝错误 Host；普通状态变更拒绝错误 Origin/CSRF；凭据写删和清除全部还拒绝过期 nonce；把 `credential_upsert` nonce 用于删除、把 `credential_delete` nonce 用于写入、跨会话使用或重放已消费 nonce 均返回403且不改变凭据；响应永不回显秘密值。

### 10.2 登录恢复

- 有效持久化会话直接进入只读处理，不调用凭据读取或认证提交；
- 会话失效后任务先暂停并持久化断点，再执行自动登录；
- 正确凭据可登录并验证绑定店铺，随后恢复到“有内容 + 未回复”第1页；
- 错误密码、账号锁定和身份不匹配均不继续评论处理；
- 验证码、短信、扫码和安全提示全部进入人工处理，自动化不尝试识别或填写；
- 连续多次用户主动触发登录也不出现冷却或429；每次动作独立、有界且同一时刻互斥；
- 旧版通用失败计数或没有明确 `credential_rejected` 证据的记录在重启后不锁定操作，也不显示“等待10分钟”或“检查账号密码”；
- 登录模式允许的认证 POST 能成功通过网络守卫；评论回复写端点、未知 POST 和所有 WebSocket 的守卫后外发计数始终为0。

### 10.3 弹窗处理

- 分别重放“重要消息”“功能升级”“新手引导”，均能在作用域内关闭并通过后置条件；
- 三个初始 `popupKey` 的关闭动作均不放行新增网络写请求；模拟关闭时发出 POST/beacon，必须被阻断且不能自动扩展白名单；
- “重要消息”遮挡底部分页时，系统关闭浮层后重试；若底部分页仍被固定栏遮挡，自动切换上方分页并保持筛选参数；
- 相同文本出现在非弹窗区域时不得误点；关闭控件候选不唯一时必须暂停；
- 未知弹窗、业务确认弹窗和安全弹窗均不自动关闭；
- 点击被遮挡时最多执行一次“处理弹窗后重试”流程，不产生无限递归；
- 已知弹窗关闭定位变化时，只有唯一且通过后置验证的修复候选可以生效，并保留回滚版本。

### 10.4 回归保护

- 完整自动恢复路径为：检测掉线 → 暂停 → 自动登录 → 关闭白名单弹窗 → 交易 → 评价管理 → 有内容 → 未回复 → 验证店铺与筛选 → 从断点继续；
- 测试前后同一评论不存在新增商家回复；回复输入框填充、回复按钮点击、回复表单提交和回复 API 外发次数均为0；
- 认证驱动无法从只读处理模块取得，自动登录代码不能调用评论回复定位键；
- 弹窗驱动只接受固定 `popupKey`，不能接收任意定位器或坐标；登录键、回复键和同名非弹窗按钮均无法通过该驱动点击；
- 在清除凭据后、删除浏览器目录前及删除目录后分别模拟崩溃，重启均从 `tmall_auth_clear.intent` 的下一未完成步骤继续，最终不残留凭据、专属浏览器目录或未完成 intent；
- 所有新增登录和弹窗数据均有对应清除入口、保留期和脱敏审计。
