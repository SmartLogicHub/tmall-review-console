# 天猫评论助手前台会话运行模式设计

## 目标

将 Windows 发布包从“托盘常驻、固定 4300 端口、可能静默复用旧服务”的运行方式，改为“当前浏览器控制台页面打开时才保持本地服务运行”的会话模式。定时自动处理保留，但仅在至少一个控制台页面保持活动时执行。

## 现状与问题

- 当前启动器固定探测并使用 `127.0.0.1:4300`；检测到健康服务就直接打开页面，无法识别该服务是否来自当前发布目录或当前版本。
- 启动器托盘常驻。关闭 Chrome 页面不会停止 Node 后端，旧服务、旧重试状态和旧前端操作错误会在后续启动中持续可见。
- DeepSeek 连接测试仅访问模型列表，无法验证实际用于分类和话术修正的 Flash、Pro 聊天请求。

## 已确认约束

- 已保存 Key 在当前电脑上对 `deepseek-v4-flash` 和 `deepseek-v4-pro` 的最小真实聊天请求均返回 HTTP 200。
- 关闭页面后不能粗暴中断已经进入天猫提交边界的操作；必须先阻止新工作，再按现有安全停止语义收尾。
- 用户接受“定时自动运行/自动回复仅在控制台页面保持打开时可用”。
- 现有工作区包含未提交的相关改动；本次只在其基础上增量修改，不重置或清理任何已有变更。

## 设计

### 启动与实例隔离

启动器为每次启动选择一个空闲的 loopback 端口，并把端口、同源 origin 和 Web 资源目录传给 Node 后端。浏览器只打开本次启动的 URL。

启动器不再把“任意一个能响应 `/api/bootstrap` 的 4300 服务”当作当前实例。若当前启动器拥有的服务仍存活，可以打开该服务；否则启动新的服务。启动日志记录本次端口和发布目录，不记录密钥或评价内容。

### 前台会话租约

前端在应用挂载时注册匿名会话标识，定期发送心跳；在 `pagehide` 时通过 beacon 或保活请求释放会话。后端只根据活动会话数量管理服务生命周期：最后一个会话关闭后，先停止新的定时触发并请求现有自动化安全停止；若宽限期内没有新的会话，则关闭应用。

刷新、短暂网络抖动或页面重新挂载不会立刻停止服务；心跳租约和短宽限期避免误关。

### 自动化与安全边界

计划任务和“立即处理一轮”仅在有活动前台会话时允许开始。最后一个会话离开时，不开始新的评价处理。已领取的工作沿用现有安全停止与提交确认策略，未完成记录继续保留为可重试、待人工确认或其他真实状态。

### DeepSeek 验证与界面状态

保存新 Key 后，设置页进入“已保存，待验证”，同时清除旧测试错误。连接测试对 Flash 和 Pro 分别发送最小真实聊天请求；返回模型级别的成功、权限、余额、限流、超时、网络或服务错误。前端只显示最近一次相关操作的结果，不再把保存成功和历史测试错误并列为当前状态。

## 不在本次范围内

- 不更换 DeepSeek 当前官方模型名。
- 不移除既有的逐条重试、重复提交防护、人工确认或投诉安全策略。
- 不让浏览器关闭后继续无人值守自动回复。
- 不迁移或删除用户当前数据库、浏览器资料、凭据或未提交文件。

## 验收标准

1. 从完整发布目录启动时，浏览器连接的是本次启动的服务，不复用旧版固定 4300 服务。
2. 控制台页面打开时，定时任务可以正常运行；关闭最后一个页面后，新任务不再启动，服务在安全收尾后自动退出。
3. Flash 和 Pro 的实际验证结果独立呈现；保存 Key 后旧网络错误不再残留。
4. 现有自动化、重试和提交保护测试保持通过，并新增启动生命周期、会话关闭和模型验证覆盖。
