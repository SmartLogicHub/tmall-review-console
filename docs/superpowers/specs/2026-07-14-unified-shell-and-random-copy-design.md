# 统一页面滚动与随机话术说明设计

## 背景与问题

当前桌面端同时使用页面滚动、固定侧栏和固定顶栏。样式表前后还存在两套互相覆盖的外壳规则：前一套按应用内部滚动设计，后一套又改成浏览器页面滚动。两种模型叠加后，侧栏、顶栏和内容区看起来像三个分开的平面，滚动时也缺少整体感。

界面还把“漫步者”和“漫步者官方旗舰店”写死在产品外壳中。这些信息既不是当前页面的必要操作信息，也会让产品难以复用于其他店铺。

“同一评价只会发送一次”描述的是提交幂等，不是话术只能使用一次。现有业务需要更明确地表达：每条新的评价都在其匹配分类的话术池中独立随机抽取；自动重新扫描不会重复处理同一评价。用户主动执行“重新生成”时属于一次明确的新生成动作，允许重新抽取话术。

## 设计目标

- 桌面端采用一个浏览器文档滚动模型，侧栏和内容区作为同一个完整页面一起滚动。
- 删除重复顶栏，减少一层无操作价值的视觉框架。
- 产品品牌改为通用的“评论助手 / 自动回复控制台”，不展示固定品牌和店铺名称。
- 用用户能理解的文案区分“不同评价独立随机抽话术”和“同一评价防重复提交”。
- 保留现有 `sourceKey` 幂等保护，不因自动刷新、自动翻页或自动重新扫描为同一评价重新抽取话术；用户主动“重新生成”仍允许重新抽取。
- 不改变自动回复提交安全边界和现有业务接口。

## 页面外壳

### 桌面端

- `.app-frame` 只负责两栏网格、圆角、边框与整体背景，高度由内容自然撑开。
- `.sidebar` 不再 `sticky`，高度随 `.app-frame` 内容区一起增长。
- `.workspace` 不再为顶栏预留网格行。
- `.page-scroll` 不建立独立滚动容器，滚动由浏览器文档统一承担。
- 删除 `topbar` 组件及其所有无用样式。

### 窄屏

- 小于等于 760px 时继续使用顶部紧凑导航，允许导航在页面顶部保持可见。
- 内容仍由浏览器文档滚动，不创建第二个滚动容器。
- 保持无水平溢出和现有四个主要入口。

## 品牌与命名

- 标志字符从品牌首字母改为通用“评”。
- 主名称为“评论助手”。
- 副名称为“自动回复控制台”。
- 删除顶部“天猫评论助手”“漫步者官方旗舰店”与重复的本机状态；连接健康状态继续在工作台现有健康卡中呈现。

## 随机话术与幂等语义

界面固定说明：

> 每条新评价都会在命中分类中随机抽取一条话术；已处理的同一评价不会重复提交。

处理规则保持为：

1. 每个新的 `sourceKey` 完成分类后，从该分类全部非空话术中等概率随机选择一次。
2. 不同评价互相独立，即使分类相同，也会分别执行随机选择；允许随机到同一句，这是正常概率结果。
3. 首次选择结果随回复草稿持久化；同一 `sourceKey` 在自动扫描中再次出现时直接跳过，不重新抽取。用户主动执行“重新生成”时允许清空旧草稿并重新抽取。
4. 提交阶段继续以 `sourceKey` 及提交状态防止同一评价被自动重复提交。
5. 话术数量少于评价数量时允许复用，不能为了“避免重复话术”牺牲随机性或造成评价漏回。

## 验证标准

- 桌面端滚动后，侧栏与内容一起移动，页面不存在独立内容滚动条。
- 页面外壳组件不再写死“漫步者”“漫步者官方旗舰店”或旧顶栏名称；商品、回复内容和客服规范中的合法品牌信息不在清理范围。
- 两条不同评价可以按注入的随机序列分别命中不同话术；重复处理同一评价不再次调用随机选择或 AI。
- 话术库页面展示新的随机与防重复说明。
- 1366×768、760×900 浏览器检查无水平溢出，导航和主要操作仍可用。
