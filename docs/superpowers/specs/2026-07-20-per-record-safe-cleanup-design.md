# 回复与投诉记录逐条安全清理设计

## 目标

“回复结果”和“投诉记录”的每一条记录都提供独立删除入口。删除后立即从当前列表消失，同时不能导致已发生的平台回复或投诉被再次提交。

## 删除语义

删除动作根据记录是否已经触达平台自动选择语义：

- 从未触达平台的失败、等待重试、尚未提交或准备中记录：删除回复草稿、投诉判断、尝试记录和本地动作锁。评价下次运行时可重新发现、重新分析。
- 已发送回复、已提交投诉、平台处理中或已有最终投诉结果的记录：删除完整运营历史、详情与尝试数据，只保留 `source_key + terminal_action + completed_at` 最小防重复标记。它不会出现在界面，也不保存评价或回复正文。
- 提交结果不确定的记录：拒绝直接删除，必须先核对平台结果，避免实际已成功却再次提交。
- 自动化正在运行或停止过程中：拒绝删除并提示先等待本轮结束，避免删除正在被执行器使用的数据。

## 服务端

- 回复逐条删除沿用 `DELETE /api/replies/:id`，扩展为返回 `mode: "reprocess" | "hidden"`。
- 新增 `DELETE /api/complaints/:id`，使用相同的两种删除模式。
- 未触达平台的投诉删除时同步清除同一 `source_key` 的回复草稿、投诉事件、投诉/回复尝试和动作锁，形成完整数据闭环。
- 已触达平台的记录删除时同步清除回复草稿、投诉详情、事件、调用和尝试数据，保留或补写 `review_action_tombstones` 中的最小终态标记。
- 所有删除动作写入审计记录，但审计记录不在运营列表中展示。

## 前端

- 回复列表每一行和详情区均提供“删除记录”按钮。
- 投诉列表每一行和详情区均提供“删除记录”按钮。
- 点击后显示与状态匹配的确认文案：
  - 未提交：删除后下次运行会重新处理。
  - 已触达平台：清除完整本地详情，只保留不可见的防重复标记，不会再次提交。
- 删除成功后清除选中项，并刷新对应列表、统计、工作台和存储统计。
- 删除失败时直接显示服务端给出的可操作原因。

## 安全边界

- 删除平台操作详情与尝试历史时，必须保留最小防重复标记。
- 不把已发送、已提交或结果不确定的记录重新开放处理。
- 不在自动化运行过程中删除记录。
- 删除单条投诉不得影响其他评价。

## 验证

- 未提交回复/投诉删除后，关联本地状态全部清除且可重新发现。
- 已发送回复和已提交投诉删除后完整历史消失，仅剩不含正文的防重复标记。
- 自动化运行时删除返回冲突错误。
- 两个页面的每条记录都能看到删除入口，确认文案和刷新行为正确。
- 全量测试、类型检查和生产构建通过。
