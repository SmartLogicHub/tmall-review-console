# 回复结果完整分页与未成功记录清理设计

## 目标

“回复结果”必须能够查看保留期内的全部记录，不再只返回最新 200 条；同时提供明确的状态筛选和“一键清理未发送成功”操作。清理后 `reply_drafts` 中只保留 `state = 'sent'` 的发送成功记录。

## 数据查询

- `GET /api/replies` 改为数据库分页查询。
- 查询参数：`page`、`pageSize`、`query`、`filter`。
- `pageSize` 默认 50，最大 100。
- `filter` 支持 `all`、`sent`、`unsent`、`good`、`bad`、`attention`。
- 搜索覆盖评论、商品、主分类、细分类和最终回复。
- 返回 `items`、筛选后 `total`、未筛选 `overallTotal`、`page`、`pageSize`、`totalPages`。
- 页码超出范围时自动落到最后一页，避免清理或筛选后出现空白死页。

## 批量清理

- `DELETE /api/storage/reviews?scope=unsent` 删除所有 `state != 'sent'` 的回复记录。
- 同时删除这些来源对应的未成功回复尝试、投诉详情和动作锁，保证页面以后仍可重新发现并处理。
- 为满足“只保留发送成功”，包括等待重试、待人工处理、提交中和提交待核对在内的所有非 `sent` 记录都会被清理。
- 自动任务处于运行或停止过程中时拒绝清理，防止与浏览器提交并发。
- `DELETE /api/storage/reviews?scope=sent` 仅清理发送成功详情，并为每个来源保留最小防重复终结标记，避免再次回复。
- 保留旧的无 `scope` 调用行为，避免已有界面或旧包调用失效。

## 界面

- 回复结果页每页显示 50 条，提供上一页、下一页和页码信息。
- 筛选项：全部、发送成功、未发送成功、好评、差评、待处理。
- 搜索、筛选和翻页全部请求后端，覆盖所有保留数据。
- 顶部显示真实总记录数；筛选后同时显示当前结果数。
- 保留原有“清理已完成记录”按钮，并新增“清理未成功记录”按钮。
- “清理已完成记录”只清理发送成功详情并保留防重复标记；“清理未成功记录”删除所有非发送成功记录。
- 清理未成功记录前提示：“将删除所有未发送成功、等待重试、待核对及处理中记录，只保留发送成功记录；以后页面仍可回复的评价会重新处理。”

## 测试

- 仓储测试验证超过 200 条仍可逐页读取、真实总数、搜索和各筛选。
- 接口测试验证分页参数、越界页码和批量清理语义。
- 清理测试验证所有非 `sent` 状态被删除、发送成功记录保留、关联失败尝试不再阻断重新发现。
- 前端测试验证筛选请求、翻页请求、真实总数和两个清理按钮。
- 完成后运行服务端与前端相关回归、类型检查和生产构建。
