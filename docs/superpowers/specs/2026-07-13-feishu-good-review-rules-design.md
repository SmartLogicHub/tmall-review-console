# 飞书好评回复规则库设计

## 目标

在现有飞书多维表格“评论回复”中新建表“好评回复规则库”，导入本地最新版 `好评回复话术（新）.xlsx` 的 13 个关键词分类。Excel 是首次导入的唯一来源；导入验收完成后，飞书表成为日常维护和程序运行时读取的规则源。程序按关键词分类匹配评论，并从该分类所有非空候选话术中随机抽取一条。候选话术字段数量可在飞书中继续向右扩展，程序无需改代码。

## 范围

本设计只覆盖：

- 新建飞书规则表并导入最新版 Excel；
- 定义表结构、读取校验、关键词匹配和随机话术选择规则；
- 定义飞书不可用时的安全降级。

本设计不覆盖：

- 修改或迁移飞书里旧的“好评话术”表；
- 商品类型、店铺等旧表字段；
- 疑似差评的具体人工处理流程；
- 天猫网页上的最终提交动作。

疑似差评判断发生在本规则库之前。被判断为“好评中的疑似差评”的评论进入现有飞书待排查流程，不调用本规则库自动回复。

## 数据源与写入原则

- 首次导入的唯一来源：`G:/桌面/天猫评论回复/好评回复话术（新）.xlsx`。
- 首次导入验收完成后，用户直接在飞书“好评回复规则库”维护后续修改；程序不再每次与 Excel 同步。
- 不参考旧飞书“好评话术”表的字段或内容。
- 新建表，不覆盖、不删除、不重命名旧表。
- 新表名称：`好评回复规则库`。
- 首次导入应得到 13 条分类记录、每条 3 个候选话术，共 39 条话术。

## 飞书表结构

| 字段名 | 飞书字段类型 | 必填 | 说明 |
|---|---|---:|---|
| 关键词分类 | 单行文本（主字段） | 是 | 分类名称，必须唯一 |
| 包含关键词 | 文本（允许多行） | 是 | 多个关键词以顿号、逗号或换行分隔 |
| 回复话术 1 | 文本（允许多行） | 否 | 首次导入的第一条候选话术 |
| 回复话术 2 | 文本（允许多行） | 否 | 首次导入的第二条候选话术 |
| 回复话术 3 | 文本（允许多行） | 否 | 首次导入的第三条候选话术 |

首次导入创建以上 5 个字段。后续用户可以新增“回复话术 4”“回复话术 5”等文本字段。程序按字段名称读取，不依赖字段排列顺序。当前版本不增加店铺、商品类型、启用状态、优先级等额外字段。

候选话术字段识别规则为 `^回复话术\s*(\d+)$`：允许数字前有或没有空格，序号必须是大于 0 的整数。字段按数字序号排序；名称不符合该规则的字段不进入随机池。同一数字不得出现两个字段，例如“回复话术 4”和“回复话术4”同时存在时视为配置错误。序号允许不连续。

## 规则读取与校验

程序在每次自动回复批次开始时读取一次飞书规则，不在批次执行过程中后台刷新。每次读取后执行以下校验：

1. “关键词分类”和“包含关键词”必须存在，并且至少存在一个符合候选话术字段识别规则的字段；首次导入必须存在“回复话术 1～3”；
2. “关键词分类”经过去空格和 Unicode NFKC 标准化后不得为空或重复；
3. “包含关键词”不得为空；
4. 每个分类在所有已识别候选话术字段中至少有一条去除首尾空格后非空的话术；各分类允许拥有不同数量的非空话术；
5. 必须存在“通用整体好评类”作为无匹配时的兜底。

任一校验失败时，不使用这批新数据替换当前有效规则；如果没有可用的历史缓存，则停止自动回复并提示检查飞书规则表。

## 关键词解析与分类匹配

- “包含关键词”支持中文顿号 `、`、中文逗号 `，`、英文逗号 `,` 和换行。
- 解析后去除首尾空格和空关键词，并在分类内去重。
- 匹配前，对评论和关键词执行 Unicode NFKC 标准化，并把拉丁字母转为小写；随后使用字面量子串包含匹配，不使用正则表达式、分词或模糊相似度。
- 一条评论可以同时命中多个分类。
- “通用整体好评类”不参与正常关键词竞争，只在没有其他分类命中时使用。
- 分类排序按以下优先级从高到低决定：
  1. 命中关键词数量更多；
  2. 最长命中关键词更长；
  3. 命中关键词总长度更长；
  4. 仍相同时，按标准化后的“关键词分类”文本升序选择，保证结果不受飞书视图排序或 API 分页影响。
- 没有关键词命中时，使用“通用整体好评类”。

该规则用于避免“物流很快”被宽泛的“很快”抢先匹配，也避免“很喜欢”同时命中多个分类时产生不稳定结果。

## 随机话术选择

命中分类后：

1. 动态识别全部符合命名规则的候选话术字段，收集当前分类行中所有去除首尾空格后非空的话术；
2. 等概率随机选择一条；
3. 每个分类独立建立随机池：某分类有 3 条非空话术就只从这 3 条中选择，有 4 条就从 4 条中选择；其他分类是否填写新增字段不影响该分类；
4. 单进程、单批次范围内，用 `lastReplyByCategory` 记录每个分类上一次选中的话术；有两条及以上候选时，从排除上一条后的候选中等概率随机选择；
5. 只有一条候选时允许重复使用；
6. 不跨分类比较重复内容。

随机选择只读取飞书内容，不回写或修改规则表。进程重启或新批次开始后不保证延续上一个批次的防重复状态；多进程并发不在本阶段范围内。

## 缓存与异常处理

- 每次批次开始调用一次 `loadRules()`。
- 飞书读取成功且校验通过后，将标准化后的规则原子写入 `data/cache/good-review-rules.json`，并标明来源时间。
- 飞书读取或校验失败时，尝试读取并重新校验该缓存；成功时由 `loadRules()` 返回 `source=cache` 和一条告警。
- 飞书和缓存均不可用时，`loadRules()` 返回错误 `NO_VALID_RULES`，当前批次停止自动回复，不使用硬编码话术。
- 告警和错误由调用方记录并展示；具体通知渠道不属于本规则库设计。

## 验收标准

- 飞书中存在独立新表“好评回复规则库”，旧表保持不变；
- 首次导入后的新表有 5 个约定字段和 13 条记录；后续允许继续新增符合命名规则的话术字段；
- 39 条回复话术与最新版 Excel 一致；
- 新增“回复话术 4”字段后无需修改程序即可被识别；
- 新增不含空格的“回复话术4”字段同样可以被识别；
- “回复话术备用”等不符合命名规则的字段会被忽略；
- 话术字段序号不连续时仍可读取，例如存在“回复话术 1、2、4”；
- 同时存在“回复话术 4”和“回复话术4”时校验失败，并按缓存降级规则处理；
- 只有 3 条非空话术的分类只从该分类的 3 条话术中随机选择，不受其他分类新增话术字段影响；
- “音质很好”能匹配“音质音效类”；
- “物流很快”优先匹配“物流配送速度类”，不会被宽泛词抢占；
- 无关键词命中的正常好评使用“通用整体好评类”；
- 同一进程、同一批次内，同一分类连续选择时，在候选不少于两条的情况下不会连续使用同一句；
- 疑似差评不会进入自动好评回复流程；
- 飞书短暂不可用时使用最近有效缓存，没有缓存时安全停止。
