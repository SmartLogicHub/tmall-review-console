# 页面优先的失败评价重新处理设计

## 目标

当天猫当前评价页面仍明确显示“评价回复”或“追评回复”入口时，以页面状态为准。数据库中的旧失败、网络失败或提交前浏览器失败不得永久阻止该评价再次处理。

## 判定边界

- 当前页面存在真实回复入口，数据库草稿为 `failed`，并且不存在真实提交边界：重新置为待处理，重新分类、选话术并提交。
- “不存在真实提交边界”包括：没有回复提交记录，或提交记录为 `failed` 且 `submitted_at` 为空。
- 人工已经确认平台未收到回复的失败记录，即使保留旧 `submitted_at`，也允许重新处理。
- 存在成功墓碑、有效动作锁、`sent`、`submitting` 或 `submission_uncertain` 记录时，继续禁止自动重发。
- 平台页面已经显示回复记录、投诉处理记录或其他平台完成状态时，继续跳过。
- 同一轮扫描使用现有 `seen` 集合，不对刚失败的同一评价循环重试；下一轮页面再次遇到时再处理。

## 数据流

1. 浏览器按页面顺序读取当前可见评价。
2. `DraftProcessor` 发现同一 `sourceKey` 的本地记录。
3. 仓储层原子判断本地失败是否属于“未跨过提交边界”。
4. 可重试时原子删除没有跨过提交边界的旧失败尝试，并重置草稿生成字段和失败状态。
5. 新草稿生成完成后，提交仓储创建新的尝试并在取得新动作锁后提交。失败尝试表本来就是每个评价只保留一个活动记录，后续重试也会覆盖旧失败字段，因此删除不会损失独立历史版本。

## 验证

- 集成测试复现“页面仍有回复入口 + 本地提交前失败”，修复前必须失败，修复后应重新生成。
- 回归测试验证曾跨过提交边界的失败不会自动重开。
- 验证成功、提交不确定、平台已处理、动作锁和墓碑保护不变。
