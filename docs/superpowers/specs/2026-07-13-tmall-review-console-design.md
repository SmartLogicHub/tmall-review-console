# 天猫评论智能自动回复控制台设计

> 登录凭据、登录态恢复与页面弹窗处理以补充规格
> [`2026-07-13-tmall-login-recovery-design.md`](./2026-07-13-tmall-login-recovery-design.md)
> 为准；补充规格覆盖本文中“只允许人工登录且不保存淘宝账号密码”的旧约束，其余只读边界继续有效。

## 目标与阶段边界

为当前 Windows 商家电脑设计并开发一套单店铺、电脑优先的本地 Web 控制台。控制台负责展示自动回复运行状态、读取飞书好评与差评模板、调用 DeepSeek 完成评论分类和模板产品信息修正，并监控天猫页面自动化元素是否健康。

第一阶段交付“真实 AI、真实飞书、真实天猫页面结构、禁止真实提交”的只读验证版本：

- 使用真实 DeepSeek API 完成评论分类与模板修正；
- 读取两张格式完全相同的飞书表：好评回复规则库、差评回复规则库；
- 连接已登录的天猫商家页面，读取评论和定位页面元素；
- 实现元素定位失效后的安全 AI 自动修复；
- 自动化底层不提供输入、点击提交、按键提交或页面脚本执行能力，并在网络层拦截非只读请求；界面明确显示“只读验证”；
- 记录系统原本准备提交的最终回复，用于验收准确性。

真实自动提交作为第二阶段独立开放项。只有第一阶段验收通过后，才新增提交能力和生产开关。

## 用户与运行环境

- 使用者：当前商家账号的单个运营人员；第一阶段不做多店铺、多用户、权限和云端部署。
- 运行位置：当前 Windows 商家电脑，控制台通过 `127.0.0.1` 本地访问。
- 设备适配：第一阶段重点支持 1366×768 及以上桌面屏幕；手机操作不在第一阶段范围内。
- 天猫登录：应用管理一个独立的 Chromium 持久化用户目录并优先复用登录态。用户可选择在控制台配置自动登录凭据；凭据只保存到 Windows Credential Manager，自动登录只允许在任务已暂停的独立认证模式中运行。详细状态机、清除规则和安全边界见登录恢复补充规格。

## 页面与组件

### 1. 运行中心

打开控制台后的默认页面，承担开始、暂停和监控任务。

- 顶部运行卡：开始、暂停、继续；第一阶段固定显示“只读验证，不会提交回复”。
- 自动回复运行带：展示当前评论所在步骤、耗时和结果。
- 指标卡：今日读取、好评数、差评数、已生成回复、失败数、AI修正产品信息次数。
- 实时队列：评论原文、星级、商品、好评/差评、匹配分类、当前状态。
- 最近结果：原始模板与最终回复的差异摘要。
- 服务健康：天猫登录、飞书同步、DeepSeek、元素定位四个状态灯。

### 2. 回复记录

- 支持按好评/差评、分类、商品、状态、日期搜索和筛选。
- 表格字段：评论原文、星级、商品标题、评论类型、匹配分类、最终回复、状态、处理时间。
- 详情抽屉展示：评论原文、当前商品信息、AI分类结果、随机抽中的完整模板、发现的其他产品信息、修改后的完整回复、DeepSeek调用信息及失败原因。
- 第一阶段状态使用 `只读已生成`，不得显示成“已回复”。

### 3. 模板配置

- 两个独立输入框：好评回复规则库链接、差评回复规则库链接。
- 两张表格式完全一致：`关键词分类`、`包含关键词`、`回复话术 1…N`。
- 控制台自动从完整飞书链接解析 Base 标识和 `table_id`；视图标识只用于打开飞书，不参与全表读取。
- 提供“测试连接”“立即同步”“查看分类”操作，并展示同步时间、分类数、话术数和字段校验结果。
- 话术字段仅匹配正则 `^回复话术\s*([1-9]\d*)$`；字段名去除首尾空格后解析序号。相同序号出现两次视为整次同步失败，序号空洞只告警、不失败。
- `关键词分类` 去除首尾空格后必须非空且在同一规则库内唯一。每个模板来源配置一个 `fallbackCategory`，必须精确匹配该表中的一个分类；好评表默认使用最新 Excel 已有的 `通用整体好评类`，差评表默认建议 `通用差评类`，但均可从已同步分类下拉选择，不强制分类统一改名。若配置项不存在且表内只有一个以“通用”开头的分类，可自动选中并提示用户；否则同步校验失败并要求明确选择。`包含关键词` 支持中文逗号、英文逗号、分号和换行分隔，分词后去空、去重。
- 每个分类至少有一条非空话术；话术按序号读取，去除首尾空白后，完全相同的重复话术只保留一条并告警，避免重复内容提高抽中概率。空白话术不进入随机池，池中每条话术等概率抽取。
- 同步先在临时版本完成全表读取和校验，全部通过后才在 SQLite 事务中原子切换活动版本。校验失败保留上一成功版本并显示错误；没有成功缓存时对应规则库不可用。
- 差评表尚未创建或链接为空时，差评流程明确显示不可用，不误用好评表。

### 4. 元素健康

- 按自动化步骤展示元素：评论列表、评论文本、星级、商品标题、回复输入框、提交按钮等。
- 每个元素显示：当前定位策略、备用策略数、最近成功时间、连续失败次数、健康度、修复版本。
- 修复记录展示：旧定位、DeepSeek候选、验证结果、启用的新定位、置信度、回滚入口和页面截图。
- 页面截图仅供本地人工查看。DeepSeek V4 为纯文本模型，第一阶段不向 DeepSeek发送截图。
- 提供“重新验证”“回滚定位”“暂停自动化”操作；回复输入框和提交按钮在第一阶段仅允许检查是否存在、唯一、可见、启用及位于预期区域，不执行聚焦、填充、按键、点击或提交测试。

### 5. 系统设置

- 天猫：登录状态、浏览器配置、只读模式状态。
- 飞书：App ID、App Secret、连接测试；密钥只发送给本地服务。
- DeepSeek：API Key、Base URL、日常模型、修复模型、连接测试和最近响应耗时。
- 默认模型：日常评论任务使用 `deepseek-v4-flash`，元素修复使用 `deepseek-v4-pro` 思考模式。
- 运行：轮询间隔、单批数量、失败重试次数；第一阶段不显示真实提交开关。
- 数据管理：显示2GB业务数据计入项、单独的Chromium登录目录及磁盘剩余空间；支持修改保留期限、预览将被清除的数据、立即清理和导出记录。

## 系统架构

### 前端

- React、TypeScript、Vite；Tailwind CSS 设计令牌配合 Radix UI 无障碍基础组件；第一阶段的少量趋势图使用轻量 SVG/CSS，不引入专用图表库。
- TanStack Query 管理服务端状态；页面级临时状态使用 React 内置状态，不额外引入全局状态库。
- 前端不直接调用 DeepSeek、飞书或天猫，不在 `localStorage` 保存任何密钥。

### 本地服务

- Node.js、TypeScript、Fastify；只监听 `127.0.0.1`。
- Playwright 启动并复用应用专属持久化 Chromium 上下文；同一用户目录只允许一个应用实例占用，检测到锁定时显示“关闭已有实例/重试”，不复制或强占浏览器目录。
- SQLite 保存配置元数据、回复记录、定位规则、修复历史和运行日志。
- DeepSeek API Key 与飞书 App Secret 保存到 Windows Credential Manager；SQLite 只保存密钥引用和非敏感配置。

### 第一期强制只读边界

- 浏览器使用三个互斥模式：`automatic_read_only`、`automatic_authentication` 和 `interactive_authentication`。登录模式必须先暂停处理任务；同一应用专属用户目录同一时刻只允许一个模式占用。完整切换规则见登录恢复补充规格。
- `ReadOnlyTmallDriver` 只暴露导航、读取文本/属性、计数、可见性、启用状态、边界框和受限定位验证，不暴露 `fill`、`type`、`press`、通用 `click`、表单提交或任意 `evaluate`。`AutomaticAuthenticationDriver` 只暴露固定认证入口中的账号/密码填充、唯一登录按钮点击和认证状态读取。`PopupDismissDriver` 只接受编译期固定 `popupKey`，在已匹配的弹窗作用域内执行该规则唯一的关闭动作；它不能接收任意定位器、页面坐标或评论回复操作键。三个驱动互不继承，也不能相互取得实例。
- `automatic_read_only` 模式禁用 Service Worker，对页面、脚本、样式、图片和数据接口全部使用显式“主机 + 路径模式 + 方法 + 用途”白名单，不因请求方法是 GET 就默认放行。确需用 POST 读取评论的接口还必须校验请求字段白名单；任何未知请求一律中止并告警。
- 仅将明确的评论回复操作键、回复表单 action 和经校验的评论回复 API 端点列入跨模式永久阻断清单，优先级高于登录、弹窗和只读白名单；不得按通用 `submit` 字样或所有表单提交一刀切阻断。认证端点（包括 `/login/submit` 类路径）只能在任务已暂停的 `automatic_authentication` 或 `interactive_authentication` 模式按精确主机、路径、方法和字段白名单放行。三个模式都默认禁止所有 WebSocket 连接，不做消息级放行；新窗口继承当前模式的同一网络守卫。初始弹窗白名单不放行任何因关闭弹窗新增的写请求。
- 每次会话记录脱敏网络审计：请求时间、方法、规范化主机/路径、允许或阻断、命中规则，不记录 Cookie、Authorization、完整查询参数或请求正文。
- 第一期编译产物中不存在“真实提交回复”服务、路由或功能开关；以后进入第二阶段时以独立模块和单独验收新增，不能通过修改数据库配置绕过只读边界。

### 本地控制台接口安全

- 服务只监听 `127.0.0.1`，并严格校验 `Host` 只能是启动时确定的 `127.0.0.1:<port>`；不接受任意 Host、局域网地址或 DNS 名称，也不启用 CORS。
- 每次应用启动生成 256 位随机本地会话令牌，仅保存在内存，通过 `HttpOnly`、`SameSite=Strict` Cookie 发给控制台；另生成 CSRF 令牌嵌入首次同源 HTML，前端只保存在内存，不写入 `localStorage`。
- 所有状态变更请求必须同时满足正确 Host、精确同源 `Origin`、`Sec-Fetch-Site: same-origin`、有效会话 Cookie 和 `X-CSRF-Token`；任一缺失均返回403。读取接口也要求会话 Cookie，防止其他网页探测本地数据。
- 破坏性接口还要求请求体携带服务端生成、5分钟有效且单次使用的确认 nonce；nonce 只在用户打开对应确认对话框后签发，不能由跨域请求获取。

### 主要接口

- `GET /api/runtime`：运行状态、只读模式和服务健康。
- `POST /api/runtime/start|pause|continue`：控制只读处理任务。
- `GET /api/dashboard`：指标、实时队列和最近结果。
- `GET /api/replies`、`GET /api/replies/:id`：查询回复记录和详情。
- `POST /api/replies/:id/reprocess`：在同一评论记录下创建新的处理 attempt，不创建重复评论。
- `GET/PUT /api/template-sources`、`POST /api/template-sources/test|sync`：管理两张飞书模板表。
- `GET /api/locators`、`GET /api/repairs`、`POST /api/locators/:operationKey/verify|rollback`：元素健康与修复管理。
- `GET/PUT /api/settings`、`POST /api/connections/deepseek|feishu/test`：非敏感设置和连接测试。
- `POST /api/browser/login/open`、`DELETE /api/browser/profile`：打开应用专属登录浏览器；删除登录目录时必须停止任务并二次确认。
- `PUT/DELETE /api/secrets/:name`：新增、替换或删除 DeepSeek/飞书密钥。写入值只进入 Windows Credential Manager，响应仅返回 `{configured, updatedAt}`，永不回显旧值或新值；写入、替换和删除都要求会话、CSRF、单次确认 nonce 并写入不含密钥的操作审计。
- `GET /api/storage`、`POST /api/storage/cleanup/preview|run`、`GET /api/storage/cleanup-events`：存储占用、清理预览、执行和审计。
- `POST /api/factory-reset/prepare|run`：签发单次确认 nonce 并执行可恢复的完整出厂重置。
- `GET /api/audit-events`：查询导出、清除、重置、配置和回滚等本地操作审计。
- `GET /api/exports/replies|repairs|logs|templates|cleanup-audit`：导出对应的脱敏记录；截图与脱敏 DOM 可按修复事件打包导出。导出文件由用户选择保存位置，不进入应用长期存储。

## 评论处理流程

1. Playwright 只读获取平台评论 ID、评论文本、星级、评论时间、商品 ID、商品标题及页面中可确认的品牌/型号/卖点字段。`storeId` 从已校验的商家后台店铺标识/URL结构化字段读取并与本地单店配置绑定，`productId` 从评论行的商品链接或结构化字段读取；两者任一缺失就暂停该批次，不用标题猜测。
2. 为评论生成稳定 `sourceKey`：优先使用 `storeId + 平台评论ID`。缺失平台评论 ID 时，先将评论文本做 Unicode NFKC、换行转空格、首尾去空、连续空白折叠为单空格并保留标点/Emoji；评论时间使用页面可见原值规范化后的原生精度；再计算 `baseHash = SHA-256(storeId + productId + 规范化评论文本 + 星级 + 规范化评论时间 + authorTokenHash)`。
3. `authorTokenHash` 优先使用页面提供的匿名作者标识；否则只在内存中对已遮罩买家显示名执行 HMAC，原显示名不落盘、不发送。HMAC 使用首次初始化时生成的安装级256位 `review_identity_salt`，保存在 Windows Credential Manager，跨应用重启保持不变，直到恢复出厂设置。若同一次抓取中仍出现相同 `baseHash` 的多条记录，则按该相同组在 DOM 中的稳定顺序生成 `baseHash#occurrenceIndex` 并记录组大小；后续组大小或顺序发生变化时，把该组标为 `identity_ambiguous` 并暂停，不允许把两条记录合并。
4. 数据库对 `sourceKey` 建唯一约束。重复轮询发现同一键时仅更新 `lastSeenAt`，不重复创建记录或调用 AI。处理中断超过 10 分钟的记录标记为 `interrupted`，启动后从最近一个已持久化步骤继续；人工“重新处理”在原记录下创建新 attempt，不复制评论记录。
5. DeepSeek Flash 返回 `library`、`libraryConfidence`、`category`、`categoryConfidence`、`reason` 和短证据。`libraryConfidence < 0.90` 直接进入 `needs_attention`，不重试、不使用通用分类；4–5 星却判为差评库、1–2 星却判为好评库时同样进入 `needs_attention`，3 星允许模型判断。
6. 模型返回的分类必须是当前活动规则库中的精确分类名。`categoryConfidence >= 0.80` 时使用具体分类；低于 0.80 时使用该模板来源配置的 `fallbackCategory`；未知分类先携带允许分类重试一次，仍未知则进入 `needs_attention`。
7. 本地程序从命中分类的非空、去重话术池中等概率随机抽取一条，并记录模板版本、分类和话术序号；随机选择不交给模型。
8. DeepSeek Flash 不返回任意改写后的整段文本，只返回针对原模板的 `edits[]`。每项编辑包含原文精确片段、该片段从左到右的1基 `occurrence`、替换文本、范围类型、冲突原因和当前商品证据引用。
9. 本地程序在原模板中枚举每个 `from` 的非重叠精确匹配，使用 `occurrence` 解析出原模板 UTF-16 索引区间；索引不存在、区间重叠或切片不等于 `from` 都拒绝。全部验证通过后按 `start` 从大到小应用编辑，因此前面的索引不会被后续替换偏移。
10. 允许的范围类型只有 `brand`、`product_name`、`model`、`product_claim`、`adjacent_connector`。前四类替换值必须来自当前页面已确认的商品事实；没有可靠替代事实时只能删除。`adjacent_connector` 仅能修改紧邻被删除片段的标点或不超过 12 个中文字符的连接语，用于保证语法通顺。
11. 编辑必须非重叠、原文精确命中，且模板其余字符逐字不变；不允许增加未经页面证实的参数、卖点、承诺、售后政策或“退货”等表达。验证失败时把违规原因交给模型重试一次，仍失败则进入 `needs_attention`。
12. 第一期把通过校验的结果保存为 `只读已生成` 并展示，不执行提交动作；第二阶段的真实提交幂等性将复用 `sourceKey`，但独立增加平台提交回执约束。

### DeepSeek 数据最小化契约

- 日常评论任务只发送：评论文本、星级、商品 ID/标题及已确认的商品事实、活动分类名/关键词、抽中模板；禁止发送买家姓名、头像、订单号、手机号、地址、Cookie、Token 或页面其他评论。
- 元素修复任务单独发送脱敏证据：去除查询参数和片段的主机+路径、脱敏页面标题、操作语义、旧定位、最多 20 个候选的标签/role/type/aria-label/placeholder/可见文本/父容器语义/粗粒度坐标。禁止发送 `value`、完整 `href/src`、Cookie、Token、任意 `data-*` 值和表单内容。
- 发送与持久化前使用同一脱敏器：手机号、邮箱、身份证样式、连续 8 位以上数字、订单/买家/收件字段及其值替换为类型标记；单候选文本最多 200 字，修复证据 JSON 总计最多 16KB，超出时按语义相似度截断。
- 本地只持久化实际发送的脱敏版本，不落盘原始 DOM/ARIA 证据。脱敏器异常或命中敏感字段但无法可靠替换时，取消本次 AI 修复并暂停，不发送原文兜底。

## DeepSeek结构化输出

- Base URL：`https://api.deepseek.com`。
- 日常任务：`deepseek-v4-flash`，关闭思考模式，使用 JSON Output。
- 元素修复：`deepseek-v4-pro`，开启思考模式并使用 JSON Output或受限工具参数。
- 分类结果固定为 `{library: "good"|"bad", libraryConfidence: 0..1, category: string, categoryConfidence: 0..1, reason: string, evidence: string[]}`；`reason` 最多 120 字，`evidence` 最多 3 条且每条必须是评论原文的短片段。
- 模板修正结果固定为 `{needsEdit: boolean, edits: [{from: string, occurrence: integer>=1, to: string, scope: "brand"|"product_name"|"model"|"product_claim"|"adjacent_connector", reason: string, evidenceFactId: string|null}]}`；条件 Schema 规定 `needsEdit=false` 时 `edits` 必须为空，`needsEdit=true` 时 `edits` 至少一项。最终回复由本地应用 edits 后产生，模型没有 `finalReply` 或自由安全标记字段。
- 元素修复结果固定为 `{operationKey: string, candidates: LocatorCandidate[]}`；最多返回3个候选，`LocatorCandidate` 固定为 `{locator: LocatorDsl, modelConfidence: 0..1, rationale: string}`，其中 `LocatorDsl` 必须匹配“受限定位 DSL”定义的封闭判别联合，`rationale` 最多120字。
- 所有输出必须通过关闭额外字段的本地 JSON Schema 校验；空内容、截断、字段缺失、越界、未知分类或受限枚举外内容时重试一次，仍失败则把当前记录置为 `needs_attention`。
- 不使用即将弃用的 `deepseek-chat` 与 `deepseek-reasoner` 别名。

## 安全元素自动修复

### 定位规则

每个自动化操作使用稳定的 `operationKey`，例如 `review.list`、`review.text`、`reply.editor`、`reply.submit`。定位规则包含：页面路径模式、元素角色、可见文本、标签、所属区域、主要定位、备用定位、预期动作、动作后条件、风险等级和版本号。

正常定位优先使用 Playwright的用户可见定位方式：role、label、text、placeholder及明确属性，避免依赖长CSS链或XPath。

### 受限定位 DSL

定位候选使用关闭额外字段的判别联合 Schema，所有文本参数最长120字：

- `role`：`{kind:"role", params:{role, name, exact}}`，`role` 只允许 `button|textbox|list|listitem|row|cell|link|heading|tab|dialog|checkbox|radio|combobox`，`name` 必填，`exact` 为布尔值。
- `label`、`text`、`placeholder`：分别为 `{kind, params:{text, exact}}`，`text` 必填，`exact` 为布尔值。
- `attribute`：`{kind:"attribute", params:{tag, name, value, exact}}`；`tag` 只允许 `button|input|textarea|div|span|li|tr|td|a`，属性名只允许 `role|type|aria-label|placeholder|name|title`，禁止 `value|href|src|style|class` 和所有 `data-*`。
- `scoped`：`{kind:"scoped", params:{container, target}}`，`container` 与 `target` 只能是上述非 scoped 类型，因此组合最多一层、总计两个简单定位器。

每种分支的 `params` 均有独立 Schema，不使用任意 `object`。本地编译器只把该 DSL 映射为 Playwright locator，不接受 CSS、XPath、正则表达式或 JavaScript。

### 自动修复触发

主要与备用定位全部失败后，收集以下文本证据：

- 当前URL、页面标题和操作步骤；
- 原定位及预期角色、文字、所属区域；
- 页面可访问性信息；
- 与旧元素相似的有限候选DOM：标签、属性、文字、周边标签、父容器和坐标；
- 最近一次成功版本。

DeepSeek Pro只能返回上述受限定位 DSL，不得返回或执行任意 JavaScript。

### 自动验证与启用

候选定位必须同时满足：

1. 只匹配一个元素；
2. 元素可见、稳定、启用，并处于预期页面区域；
3. 角色、可见文字和周边上下文与原操作语义一致；
4. 只读属性检查通过；第一阶段不使用点击、聚焦、填充或按键来验证动作；
5. 本地语义分数按角色 35%、标签/文字 25%、所属容器 20%、页面路径 10%、稳定属性 10% 计算。普通读取元素要求模型置信度 `>=0.92` 且本地分数 `>=0.85`；`reply.editor`、`reply.submit` 等观察型高风险元素要求模型置信度 `>=0.97` 且本地分数 `>=0.95`；
6. 高风险元素必须同时满足角色、标签/文字、所属容器和页面路径四类信号，不得仅凭坐标、CSS 类名或模型置信度启用。

各子分数使用固定算法：角色与预期 role 精确一致为1，否则0；文字先做 NFKC、英文小写、折叠空白和去首尾标点，精确一致为1、双方任一包含另一方且短文本至少2字为0.8、否则以 `1 - Levenshtein距离/较长文本长度` 计算且低于0.7记0；容器精确命中配置的容器定位为1、仅落在同一命名区域为0.5、否则0；页面路径命中配置模式为1、否则0；稳定属性全部与上一成功版本一致为1、部分一致为0.5、没有一致项为0。高风险规则若上一版本没有可验证的稳定属性，不允许自动启用，只能告警等待人工更新基线。

满足全部条件时自动保存为新版本并继续只读流程；候选不唯一、置信不足或验证失败时暂停当前流程并在控制台告警。所有修复都保留旧版本，可一键回滚。

## 状态与数据模型

- 运行状态：`stopped`、`running_read_only`、`paused`、`error`。
- 回复记录：`discovered`、`classifying`、`template_selected`、`rewriting`、`read_only_ready`、`interrupted`、`identity_ambiguous`、`needs_attention`、`failed`。
- 元素健康：`healthy`、`degraded`、`healing`、`paused`。
- 修复事件至少记录：operationKey、旧版本、候选定位、验证明细、置信度、新版本、截图路径、时间和结果。

## 数据生命周期与清理闭环

系统只保存完成运行、排错和复核所需的数据。每类数据都必须在创建代码旁声明保留策略，不允许新增“无期限保存但没有清除入口”的数据表或文件目录。

### 默认保留策略

| 数据类型 | 默认保留 | 导出策略 | 清除方式 |
|---|---:|---|---|
| 评论、处理 attempt 与最终回复 | 90天 | CSV 或含处理明细的 JSON | 每日自动清理；支持筛选导出和手动清除 |
| AI结构化结果 | 30天 | 随回复明细 JSON 导出 | 随评论记录关联清理；不单独残留 |
| DeepSeek原始响应 | 7天 | 可按记录导出脱敏 JSON；显示敏感内容警告 | 自动清理；不保存思维链内容 |
| 页面截图 | 14天 | 可按修复事件导出压缩包 | 自动清理；可按修复事件手动删除 |
| 脱敏DOM/可访问性快照 | 14天 | 可与修复事件一起导出 | 自动清理；与截图同批删除 |
| 运行与网络审计日志 | 30天 | 脱敏 JSONL | 按日期滚动清理 |
| 飞书模板缓存 | 最近5个成功版本 | JSON；保留版本和来源表标识 | 新版本写入后删除更旧版本 |
| 元素定位版本与修复事件 | 当前版本和最近10个历史版本/operationKey | JSON；截图和快照单独选择 | 新版本生效后删除更旧历史；绝不删除当前版本 |
| 操作与清理审计 | 180天 | CSV | 只保留动作、类型、数量、空间、时间和结果，不保留原内容 |
| 非敏感设置 | 当前值 | JSON | 恢复出厂设置或逐项恢复默认 |
| 浏览器登录数据 | 直到用户主动退出或恢复出厂设置 | 不提供导出 | 通过“退出并清除登录数据”或恢复出厂设置显式清除，不参与日常自动清理 |
| API密钥 | 直到用户删除配置或恢复出厂设置 | 永不导出 | 从Windows Credential Manager显式删除，不写入日志或数据库 |
| 评论身份HMAC密钥 | 从首次初始化到恢复出厂设置 | 永不导出、回显或人工编辑 | 以 `review_identity_salt` 保存于Windows Credential Manager；仅恢复出厂设置时删除 |

### 自动清理任务

- 每天本地时间03:30执行；电脑关机错过时，在下次启动后补执行一次。
- 清理前根据当前时间和配置计算候选数据，使用同一规则提供控制台“清理预览”。
- 清理顺序为临时文件、截图/DOM、原始AI响应、日志、回复记录、历史版本，避免先删除索引后留下孤立文件。
- 数据库记录与关联文件按事务式流程处理：先标记清理批次、删除允许目录中的文件、删除数据库记录、写入清理审计；失败时保留批次状态并在下次重试。
- 文件删除只能发生在应用数据根目录的截图、快照、缓存、日志和临时导出白名单目录中；删除前校验规范化绝对路径，禁止使用用户输入路径递归删除。
- 单次删除大量SQLite记录后执行合适的checkpoint；仅在释放空间确有必要时执行数据库压缩，避免每天无意义重写数据库。

### 手动数据管理

- 用户可以按数据类型和时间范围预览数量与预计释放空间，然后二次确认清除。
- “清除运行记录”不影响飞书模板、元素当前定位、API密钥或天猫登录态。
- “恢复出厂设置”是独立高风险操作：停止任务、提供可选导出、要求输入确认短语，然后清除数据库、截图/快照/日志/缓存、模板来源与定位版本、应用专属浏览器目录以及本应用在 Windows Credential Manager 中的全部密钥；不触碰用户的日常 Chrome 配置或用户选择保存到应用目录外的导出文件。
- 恢复前在白名单临时目录写入仅含随机操作ID和开始时间的 reset intent；清除后重新初始化最小数据库，写入一条 `factory_reset_completed` 审计再删除 intent。若中途崩溃，下次启动只允许继续完成恢复；失败则在新数据库记录 `factory_reset_failed`，不重新装载半清除的旧数据。
- 导出成功后不自动删除源数据；用户需要明确选择“导出后清除”。
- 所有导出、手动删除、应用重置、保留期限变更、密钥新增/替换/删除、浏览器登录数据清除、模板来源变更和定位回滚都写入操作审计；审计记录 `local_user`、时间、动作、脱敏参数摘要、影响数量、结果和错误码，不记录密钥值或被删除原文。
- 操作审计自身到期时按天聚合清理，不为每条过期审计再递归创建审计；只写一条该批次的数量与结果，且同样遵守180天保留期。

### 存储保护

- 应用数据默认软上限2GB，可在设置中调整。计入范围固定为应用数据根目录下的 SQLite 主文件及 WAL/SHM、日志、截图、脱敏快照、AI 原始响应、模板缓存、定位/修复产物、清理临时文件、reset intent 和未完成的临时导出。
- 应用专属 Chromium 用户目录不计入2GB业务数据软上限，避免浏览器缓存导致业务数据被误判；控制台必须单独显示其占用。用户保存到应用数据根目录外的导出文件也不计入。两类排除数据仍受所在磁盘的硬保护，恢复出厂设置会清除 Chromium 目录但不会清除外部导出。
- 达到80%时在运行中心和系统设置显示告警；达到100%时先清理已过期数据，仍超限则暂停整个处理任务，拒绝创建新的评论、AI调用、截图、快照和日志批次，只保留现有数据读取及清理/导出功能，不静默删除未过期记录。
- 另设磁盘硬保护：应用数据所在磁盘可用空间低于 `max(1GB, 磁盘总容量的2%)` 时，无论软上限占用多少都禁止启动或继续处理。若空间在一次写入期间跌破阈值，立即停止新工作并尽力写入一条不超过4KB的状态事件；写入失败则只在内存和界面显示告警。
- 启动任务、开始新批次、保存截图/快照及发起 AI 调用前均检查软上限和磁盘硬保护；只有用户完成清理或扩容并通过复检后才能继续。
- 控制台显示各类数据占用、最近清理时间、下次计划清理时间和最近一次清理结果。

## 异常与降级

- 飞书不可用：使用最近一次通过校验的只读缓存；没有缓存时暂停评论处理。
- DeepSeek不可用：不使用未经修改的产品专属模板冒险继续，当前评论标记失败。
- 天猫登录失效：停止读取并在顶部显示登录提醒。
- 元素定位不确定：暂停，不使用坐标盲点，也不强制点击。
- SQLite或本地服务异常：界面显示明确错误，不伪造运行状态。
- 自动清理失败：不影响现有记录读取，但显示存储告警并在下次启动重试；磁盘空间不足时按存储保护规则降级。

## 验收标准

### 界面

- 五个页面完整可操作，视觉与参考图方向一致；1366×768和1600×900无横向溢出、文字截断或关键按钮遮挡。
- 开始、暂停、继续、筛选、详情抽屉、连接测试、同步、元素验证和回滚交互有完整加载、空状态、成功和失败状态。
- 第一阶段所有页面明确显示“只读验证”，任何位置都不出现可执行真实提交的控件。
- 数据管理能够按类型展示占用空间、预览清理范围、执行清理并显示清理审计；手动清除运行记录不会删除登录态、密钥、模板配置或当前元素定位。
- 从外部网页、错误 Host、错误 Origin、缺少会话 Cookie、缺少 CSRF 头或复用过期确认 nonce 调用本地读取/破坏性接口均被拒绝；正常同源控制台操作不受影响。

### 评论与AI

- 建立一套经人工标注并固定版本的40条验收语料：10条明确好评、10条明确差评、10条星级/文本冲突或低置信度评论、10条含错误产品名/型号/卖点的模板修正案例。明确样本的规则库准确率不低于95%、具体分类准确率不低于90%；冲突样本不得错误自动生成，必须进入 `needs_attention` 或命中人工标注的允许结果。
- 使用真实 DeepSeek 完成验收语料测试，返回结果均通过严格 Schema 校验；同时使用固定模型桩覆盖每个阈值边界和失败分支，避免把非确定性模型输出当成唯一自动化测试依据。
- 程序而非模型完成随机话术选择；记录能够同时展示原始模板和最终回复。
- 模板修正验收中，本地编辑校验器必须拒绝100%的越界修改、重叠编辑、原文不匹配和无证据卖点；所有接受结果的非编辑区域与原模板逐字一致，无法确认的专属信息只删除、不编造。
- 加入同一产品词在模板中出现两次的案例，分别修改第1次和第2次 occurrence；解析出的 UTF-16 切片必须准确，按倒序应用后不影响另一处文本。
- 相同评论连续轮询三次只产生一个 `sourceKey` 和一次 AI 处理；模拟各阶段崩溃后可从最近持久化步骤恢复，人工重试只新增 attempt。
- 同一商品下两位买家在相同时间留下相同文本和星级时必须生成两个不同键；模拟碰撞组顺序/数量变化时进入 `identity_ambiguous`，不得误合并。
- 缺少平台评论 ID 的同一评论在应用重启前后生成相同 `sourceKey`；恢复出厂设置会删除并重建 `review_identity_salt`，旧盐从不出现在数据库、日志、导出或界面中。
- 好评和差评表均覆盖：动态话术列、序号空洞、重复序号、重复分类、重复话术、`fallbackCategory` 不存在、未配置时存在多个“通用”候选、空随机池、无效同步保留旧版本和缓存原子切换；新增合法 `回复话术 N` 无需改代码。
- 脱敏测试注入手机号、邮箱、身份证样式、订单号、买家字段、Cookie、Token 和带查询参数 URL；发送给 DeepSeek 和落盘快照中不得出现原值，超出16KB的修复证据按规则截断。

### 元素修复

- 在测试页面中分别模拟CSS类变化、DOM增加包裹层、按钮文案小幅变化和候选元素重复；前三类可在验证通过后自动修复，候选重复必须暂停。
- 对每种定位 DSL 分支、非法属性、额外字段、scoped 二次嵌套、120字超长参数和语义评分临界值建立测试；非法候选不得被编译或保存。
- 在真实天猫登录页面完成只读定位验证；分别统计 `blockedWriteAttemptCount` 与守卫之后捕获层记录的 `egressWriteRequestCount`：前者允许大于0并必须有阻断审计，后者必须始终为0。测试前后重新只读读取同一评论，确认页面没有新增商家回复；未知请求允许次数为0，回复输入框/提交按钮上的填充、按键、点击、表单提交和页面脚本命令调用次数均为0。

- 每次修复都有可查看的证据、版本和回滚记录。

### 数据生命周期

- 为每类持久化数据验证默认保留期限；构造过期与未过期数据后，自动清理只删除过期数据及其关联文件。
- 模拟清理中断后可以安全重试，不产生孤立文件、重复审计或删除未过期数据。
- 路径安全测试证明清理任务不能删除应用数据白名单目录之外的任何文件。
- 2GB软上限、80%告警、100%暂停和磁盘硬保护可通过测试配置触发；达到硬保护后不得新增业务记录或发起 AI 调用，完成清理并复检后才能继续。
- 每种持久数据均验证对应导出或明确不可导出策略；导出、手动删除、重置、保留期变更、密钥删除、登录数据清除和定位回滚均产生不含敏感原值的操作审计。
- 2GB占用计算逐项覆盖 SQLite 主文件/WAL/SHM、各产物目录和临时文件；Chromium目录与外部导出不计入但单独显示，三者均能触发整盘硬保护。
- 密钥新增、替换和删除接口在正常同源条件下只返回配置状态；错误Host/Origin/CSRF/nonce均被拒绝，任何响应、日志、审计和导出中都不出现密钥值。
