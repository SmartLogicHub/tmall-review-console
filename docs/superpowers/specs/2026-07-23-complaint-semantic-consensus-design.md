# 投诉语义一致性与正文事实校验设计

## 目标

提高真实可投诉评价进入天猫投诉提交流程的概率，同时保留最终页面定位、防重复提交和点击后不确定性保护。

## 设计

1. 两次独立模型调用仍然必须真实发生并可追踪，但候选一致性只比较官方投诉类型与核心事实代码，不再要求引用起止位置完全相同。
2. 每次确认仍保存自己的引用范围，并用该次真实模型调用的身份摘要校验，防止复制或伪造确认。
3. 两轮类型或事实代码冲突时继续使用第三轮裁决；第三轮只要在语义身份上匹配前两轮之一即可形成两次独立确认。
4. 正文硬事实校验按投诉类型使用保守的确定性规则。新增规则只处理正文能够直接证明的场景；依赖签收状态和图片来源的平台事实继续拒绝自动投诉。
5. 投诉入口、官方类型、描述回读、唯一提交按钮、提交前检查、点击后不确定性和已投诉跳过逻辑保持不变。

## 正文可验证边界

- 保留：无意义内容、针对具体人员的辱骂、广告引流。
- 新增：明确的错商品评价语境、第三方隐私、明确敏感或暴恐宣传、明确低俗色情内容、违禁品交易推广、针对未成年人的有害内容、以改删评价为条件索取额外利益、明确同行身份与恶意报复。
- 继续要求外部证据：未签收却描述使用体验、虚假或网络图片。

## 验证

- 回归测试证明相同类型与事实代码、不同引用边界时不触发第三轮并能形成可信确认。
- 回归测试覆盖新增正文事实的正例和普通售后、普通商品使用等反例。
- 投诉专项测试、服务端全量测试、类型检查和构建全部通过后才交付。
