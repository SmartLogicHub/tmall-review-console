# 天猫浏览器稳定节奏与页面元素验收设计

日期：2026-07-16

## 目标

解决登录页一次性快速填充、过早判定登录失败，以及页面元素变化时流程无从判断的问题。浏览器操作以兼容性、可观察性和安全后置条件为核心，并保留用户最新指定的 `patchright` 与人性化延迟实现，同时不降低回复提交保护。

## 设计选择

采用“条件驱动 + 有界人性化节奏”的统一浏览器动作层：输入类动作逐字触发页面事件，点击和导航类动作在操作前验证唯一性与可用性，操作后必须等待明确页面状态，再增加 Claude 已实现的有界随机停顿。浏览器驱动改用 `patchright` 并继续使用持久化 Chrome 上下文。随机延迟只控制操作节奏，不能作为页面成功、提交成功或队列为空的证据。

## 操作节奏

- 账号与密码先清空，再逐字输入；保留 Claude 的每字符 60～180 毫秒随机间隔和少量 300～800 毫秒思考停顿，输入完成后仍校验最终值。
- 字段切换、点击前后、导航、筛选和评价间隔保留 Claude 的有界随机延迟；随机范围集中定义并验证，业务代码不得散落新的任意范围。
- 普通筛选与导航点击前仍要求元素唯一、可见且可用；随机延迟结束后必须继续等待明确的后置状态，不能仅因等待结束就判定成功。
- 回复或投诉等高风险入口只通过明确后置条件确认打开；提交动作继续使用原有高风险定位审批和幂等保护。
- 所有等待有明确上限：登录结果 20 秒、页面导航 20 秒、筛选及列表变化 15 秒、弹窗开关 8 秒。达到上限时返回用户可理解的中文状态，不无限等待，也不把超时当成成功。
- 人性化延迟参数为产品内部默认值，本阶段不增加用户可调速度设置；测试必须注入可控随机源和无等待实现，避免测试随机失败或变慢。

## 浏览器运行时集成

- 使用 `patchright@^1.61.1` 作为生产浏览器驱动；不再引入 `playwright-extra` 或 `puppeteer-extra-plugin-stealth`。
- 保留 Claude 的随机 viewport 和 Chrome 启动参数；持久化 profile、可见浏览器、中文 locale 及现有会话恢复规则不变。
- `patchright` 的 `chromium.launchPersistentContext` 必须通过可注入运行时边界测试，避免真实浏览器成为单元测试依赖。
- 人性化延迟模块使用有界整数随机值；非法范围必须立即失败，不能产生负等待、无限等待或测试挂起。
- 队列中每条评价处理后的默认间隔保留 3～8 秒，并允许测试注入 no-op；延迟前和延迟后都必须重新检查时间窗口、暂停和停止状态，状态已变化时不得开始下一条。

## 登录状态机

1. 打开千牛商家首页并判断是否进入登录页。
2. 在主页面及任意层级子框架中查找登录控件组。账号框、密码框和登录按钮必须位于同一个框架，并且整个框架树中只能有一个同时满足三个控件条件的框架；不得跨框架拼接控件。
3. 优先使用当前已批准定位；旧定位失效时，仅允许唯一且通过可见性、可编辑性或可用性验证的低风险备用定位。每个控件在目标框架内也必须唯一。
4. 逐字输入账号和密码，并在本地内存中校验输入框内容与待输入内容一致；任何内容不得写入日志。
5. 验证登录按钮唯一、可见、可用，等待稳定节奏后点击。
6. 最多等待 20 秒，直到出现以下明确结果之一：
   - 离开登录页并进入商家页面；
   - 出现验证码、扫码、电话/短信、安全或身份验证；
   - 出现尚未确认用途的滑动控件；
   - 出现账号或密码错误等可公开错误提示；
   - 超时，返回“登录结果暂未确认”。
7. 电话/短信验证及未确认用途的滑动控件由浏览器驱动返回既有 `manual_verification_required` 认证结果；API 和自动化控制器将其映射为正式运行状态 `manual_action_required`。保持同一个持久化浏览器上下文、窗口和认证会话，不关闭、不新建上下文，也不再次自动提交账号密码。
8. 人工接管时自动任务停止开始下一条评价。用户在原窗口完成验证后点击“重新检测并继续”：控制器复用同一上下文重新执行登录态、店铺身份和评价页导航检查；成功则转为 `authenticated`，运行任务根据原触发方式恢复，失败仍保持 `manual_action_required`，明确密码错误才转为 `failed`。
9. 登录成功后核对目标店铺，并导航至评价管理页；身份不符立即停止。验证成功后的登录态由现有持久化浏览器配置复用。

## 页面元素验收清单

每个元素记录操作键、用户名称、风险级别、当前定位、备用定位、唯一性条件和操作后必须出现的状态。真实验收只读进行。

### 登录页

- 登录账号框：唯一、可见、可编辑。
- 登录密码框：唯一、可见、可编辑、密码输入类型。
- 登录按钮：唯一、可见、可用。
- 验证码、安全验证、扫码确认、电话/短信验证：只识别并暂停，不尝试绕过。
- 滑动控件：在没有证据证明其为普通低风险控件前，一律暂停并交由人工操作；不得按坐标自动拖动。
- 登录错误提示：仅读取白名单中的用户可理解错误，不保存完整页面。

### 评价页导航与筛选

- `交易` 菜单和 `评价管理` 入口。
- `来自买家的评价` 页签。
- 评价日期控件、上月/下月按钮和日期单元格。
- 快捷日期：今天、昨天、近 7 天、近 30 天；自定义日期必须核对起止值。
- `有内容` 与 `未回复` 筛选器。
- 搜索按钮及筛选完成后的列表稳定证据。
- 安全通知弹窗关闭按钮；退款、投诉、处罚、验证码和业务确认弹窗禁止自动关闭。

对应后置条件固定为：`交易` 后侧栏出现评价管理入口；`评价管理` 后 URL 或评价管理页签成立；日期操作后控件值等于目标区间；`有内容`、`未回复` 后选中状态成立；搜索后列表稳定证据发生变化或出现经过验证的空队列证据；分页后活动页码与目标页一致。

### 评价列表与实时队列

- 评价列表区域与空队列证据。
- 评价唯一标识、评价原文、评价时间。
- 商品标题、商品 ID、订单号与买家脱敏信息。
- 当前页码、下一页、上一页及不可继续分页状态。
- 完全沿用既有实时队列算法：每次回复提交、投诉提交或人工分流等外部动作后重新获取未回复列表；使用稳定 `sourceKey` 跳过已经处理或持有的评价；只有连续两次完整扫描都没有发现新评价，并且每次扫描末尾的第一页最终检查也没有新评价，才判定队列为空。处理期间新增评价会在后续扫描中进入同一轮。
- 已见 `sourceKey` 去重只防止同一条评价重复提交，不影响不同评价随机抽取同分类话术。

### 回复与投诉入口

- `评价回复`、`追评回复` 入口。
- 回复编辑器、提交按钮和明确成功标识。
- `投诉评价` 入口、投诉类型选择和下一步页面。
- 投诉描述框、提交按钮和结果标识。
- 真实只读元素验收只允许固定审计操作键 `audit.reply.open`、`audit.reply.cancel`、`audit.complaint.open`、`audit.complaint.cancel`；它们只能打开首层入口并立即取消，不接受任意选择器或通用点击参数，不填写回复、不选择投诉类型、不填写投诉描述、不提交。
- 回复编辑器、回复提交按钮、投诉类型、投诉描述框、投诉提交按钮均为高风险元素，新定位必须人工批准后才能用于正式写入。
- 首层真实只读验收无法安全出现的投诉下一步页面、描述框、提交按钮和提交后结果标识，只能通过脱敏测试夹具与既有正式流程的审批后验证覆盖；不得为了审计放宽只读驱动能力。正式流程中只有在用户已批准的投诉自动化启用后，才能按官方类型进入下一步。

## 元素失效与恢复

- 低风险导航、筛选和分页定位失效时，备用候选必须唯一、可见、可用，并通过操作后页面状态验证，才可记录为候选版本。
- 登录输入框可使用已验证的低风险备用定位完成当前登录，但仍记录旧规则失效，便于后续更新元素版本。
- 高风险写入元素不自动切换到新版本；生成候选后进入人工批准状态。
- 任意候选不唯一、后置条件不成立或页面状态不明时，停止相关流程并保留旧版本。
- 不执行任意脚本、不使用屏幕坐标点击、不自动操作安全或业务确认弹窗。

## 诊断与数据安全

- 诊断只记录操作键、阶段、候选数量、页面类型、耗时和脱敏错误类别。
- 不记录账号、密码、API 密钥、验证码、Cookie、认证响应、输入框内容或完整登录页面。
- 可公开的页面错误只保留规范化类别，例如“账号或密码错误”“需要安全验证”“页面响应超时”。
- DOM 证据沿用现有脱敏与保留规则；正常日志不持久化原始 DOM。

## 测试与真实验收

- 单元测试验证旧定位回退仅接受唯一、可见且符合可编辑/可用条件的控件。
- DOM 测试验证人性化逐字输入会触发键盘事件，字段被正确清空且输入完整。
- 可控随机源与时钟测试验证所有随机值落在批准范围内、测试可复现，并验证 20 秒明确结果上限不会被随机延迟或探针耗时突破。
- 运行时测试验证 patchright 持久化上下文、随机 viewport 和启动参数与当前 Chrome 驱动兼容。
- 状态机测试覆盖登录成功、密码错误、验证码、安全验证和结果超时，并验证三个登录控件必须来自全局唯一的同一框架。
- 状态机测试覆盖首次电话/短信验证、滑动控件保守暂停，以及人工完成后从当前会话重新检测并继续。
- 元素合同测试覆盖导航、筛选、日期、分页、列表身份字段、回复与投诉入口，以及各动作固定后置条件和等待上限。
- 投诉深层元素与提交后标识使用脱敏测试夹具验证；真实只读验收只验证固定首层打开/取消操作键。
- 真实只读验收逐步记录每个元素的匹配数和后置状态；回复与投诉弹窗打开后立即取消，不产生外部写入。
- 最后运行服务器、前端、领域层、端到端测试、类型检查、构建和敏感信息扫描。

## 验收标准

- 登录表单不再因一次性快速填充或过早判断而误报失败。
- 登录后的每一步都有唯一元素验证和明确后置状态。
- 能区分登录失败、安全验证和结果超时。
- 页面元素验收不产生评价回复、投诉或其他业务写入。
- 新节奏不会取消幂等、店铺核对、高风险元素审批或不确定提交保护。
